# 成果登记与草稿预览

日期：2026-11-06。范围：源码和配套平台工具契约；未打包、替换应用或部署线上。

原有缺口：普通文件写入没有成果登记事件；分段/旧文档草稿虽持久化，但界面只展示已发布成果。

实现：

- 新增类型化 `register_document`。内核明确指定 Markdown 文件、名称和 SHA-256；复用本机文件权限读取，再校验读取内容的哈希。以原文字节保存独立成果快照，发送既有 artifact 事件。源文件不被搬动或覆盖；同一调用标识重放不重复创建成果。
- `read_file` 返回 SHA-256；平台工具白名单及诊断工具名称目录同步扩展。
- 聊天历史返回原生及旧草稿元数据，新增按账号、聊天双重限制的 `document.draft.read`。分段提交发送 drafts 事件，运行结束补发当前目录；草稿正文按需读取，不混入已发布文档表。
- 聊天卡片、文档列表及预览支持“未完成草稿”，草稿禁用打开/另存/编辑，提交后移除对应原生草稿入口。旧草稿不自动发布，旧消息不被改写。

验证：构建通过；桌面 181/181、平台 60/60。新增 4 个回归用例覆盖授权读取、哈希冲突、稳定调用去重、原始字节、源文件后续修改不改变快照、重启恢复、跨账号与跨聊天拒绝、分段提交后移除草稿，以及 4212 字旧草稿完整读取。

实际 Electron + IPC + Node 工作进程 + Harness SDK + 隔离平台通过。模型响应采用夹具，文件授权、读取、成果写入、草稿预览、提交后替换、成果卡片与重载均走实际链路。不能据此声称真实模型总能主动选择登记工具。

源码入口：`apps/desktop/harness-tools.mjs`、`apps/desktop/chat-service.mjs`、`apps/desktop/renderer/documents.js`、`apps/desktop/renderer/chat.js`。

验证入口：`node --test apps/desktop/test/artifact-pipe.test.mjs`、桌面完整测试、平台完整测试及 `pnpm test:desktop:chat`。
