## 故障定位

最后两项工具在16:38:32.890前均返回成功。第21次模型请求为 `loop-77dd1b3b-ed46-488f-9f4d-3c9791b9402c`，未收到HTTP响应状态，16:38:37.091结束。记录为 `MODEL_CONNECTION_FAILED / model_connect / UND_ERR_SOCKET / httpStatus=0`。

该错误来自桌面Harness适配器向当前平台 `/v1/harness/completions` 发起 fetch。后续只读查询平台容器日志确认：同一个loop请求在16:38:37.147被平台记录为HTTP 400，耗时2680ms。前20轮均有harness_request_finished成功记录，第21轮只有HTTP 400记录，没有进入模型执行的结束记录。不能将桌面文案解释为模型供应商连接失败；桌面没有收到平台的错误响应。

当前最有力的解释是平台请求体超限：当前HTTP入口给Harness设定262144字节上限；readBody超限后调用req.destroy()，catch才尝试返回400。这会使客户端看到socket异常，同时服务端日志仍记录400。JSON解析失败及模型/工具契约不符也是400来源，但工具目录前20轮一致且正常。
