# 异常提醒与额度自动审批验收

日期：2026-10-28。范围：源码实现、隔离平台与真实Electron验证；未发布生产平台、未替换已安装APP，未修改生产账号额度。

## 结果

- 额度不足自动弹窗：显示原因、影响、保留进度、实际可用tokens、上限与最低调用预留，并直接申请新增额度。
- 当前额度申请自动审批，每次新增1至100万tokens；服务端校验当前账号，额度增加与审计在同一事务内完成。
- 同一申请按账号及编号幂等；编号在请求发送前保存到本机，响应丢失时复用核实。模拟“已批准但客户端未收到响应”后未重复增加额度。
- 批准成功与任务可恢复分别判断：新增1token仍低于100token最低预留时继续提示不足；补足后才显示到账与继续入口。
- 原已用额度、未知用量、并发限制与即梦积分不被清零或改写。已有生成/写入不能整轮重放，仅只读准备可安全继续。
- 原始429保留平台的额度或并发原因；模型额度与即梦积分明确区分。额度读失败且登录失效时给出重新登录入口，不误称平台缺少申请能力。
- 提醒统一说明原因、影响、保留内容和下一步；技术信息折叠。恢复图片后更新原提醒为已恢复，不以旧失败文案覆盖真实成果。
