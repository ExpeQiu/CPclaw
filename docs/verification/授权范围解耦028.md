# 授权范围与对话权限解耦验收

2026-10-27。修复默认「请求批准」模式下授权范围被锁死为「仅当前操作」的问题。

## 问题

授权弹窗的「授权范围」下拉有三个选项：本次任务、本次对话、仅当前操作。宿主按对话权限模式计算 `canAuthorizeTask` / `canAuthorizeAuto`，两个开关都带 `permission.mode!=='ask'` 条件。默认对话权限为「请求批准」（`ask`），因此两个开关恒为 false，前端禁用两个可复用选项并回退到「仅当前操作」。结果是：无论用户在弹窗里怎么选，一次批准都只能覆盖单个操作，无法一次授权整段任务。

## 改动

- `apps/desktop/service-runtime.mjs`：`canAuthorizeTask` 只依赖任务标识、`canAuthorizeAuto` 只依赖账号与对话标识，不再受对话权限模式限制。授权范围以用户在弹窗内的显式选择为准。
- 复用判定同步调整：已保存授权按自身范围复用（本次对话授权跨任务有效，本次任务授权仅同任务有效），不再因对话权限模式为 `ask` 而作废。
- 弹窗新增「当前对话权限」上下文行，并显示当前对话权限名称，说明两层含义相互独立。
- `apps/desktop/renderer/extensions.js`：授权范围说明补充失效时机。

对话权限仍是「是否需要询问」的开关，「帮我批准」与「完全访问权限」只影响自动放行，不改变弹窗内可选范围。

## 边界

- 「本次任务」需要任务标识，「本次对话」需要账号与对话标识；缺少对应标识时该选项不可选。
- 登录与支付等 `forceApproval` 场景仍每次询问，不受范围选择影响。
- 即梦积分只展示本次报价与已预留额度，不提供可编辑上限；额度不足时再次确认即可按报价追加预留。
- 授权绑定服务地址、本机程序真实路径和内容指纹，不扩展到其他服务或被替换的程序。

## 验证

- `node --test apps/desktop/test/*.test.mjs`：104 项通过（新增 5 项）。新增用例覆盖「请求批准」模式下任务级与对话级范围可选、缺少身份标识时只能单次授权、任务授权在任务内复用、新任务重新确认、单次授权不覆盖后续操作、授权状态上报。
- `scripts/verify-conversation-permissions.mjs`：Electron + 宿主 IPC + 真实文件与终端命令通过。验证弹窗默认选项为「本次任务」、两个可复用范围可选、上下文显示当前对话权限、单次授权不覆盖后续、任务授权在任务内复用，以及既有的三模式隔离、降权中止、账号与对话隔离、窄窗口布局。
- `scripts/verify-service-consent.mjs`：既有任务授权、Auto 跨任务、撤销、Escape、累计额度回归通过。
- 未消耗真实积分，未操作真实第三方业务。
