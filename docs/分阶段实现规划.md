## 1. 功能落在哪一阶段

| 阶段 | 交付的功能 | 员工可见结果 | 通过之前不算完成 |
|---|---|---|---|
| P0 技术验证 | 工程骨架、Harness 子进程、受控写文件、MiniMax-M3 流式调用、取消与进程回收 | 本机用合成材料生成 `report.md`；问答/规划写不了文件 | 开发机跑通；签名安装包 |
| P1 云端基础 | 登录、设备会话、组织权限、模型网关、最小管理端 | 登录后续期、退出、撤销；员工调不到管理接口 | 只校验 JWT 过期 |
| P2 本地工作台 | 三栏任务、模式与预算、审阅恢复、一个 CLI、一个 MCP、项目/记忆、Personal Wiki | 授权目录里的报告可打开、可拒绝、可恢复；个人知识可引用 | 企业知识总闭环 |
| P3 企业资源 | Skill 发布与安装、私有文件上传、日志补传、企业原文与 Enterprise Wiki、授权学习后他人复用 | 获准员工用到固定版本；无权员工看不到 | 待审内容出现在公共目录 |
| P4 办公入口 | 飞书、企业微信单聊，在线 PC 执行并回原会话 | 两个渠道各自问得通；离线明确不可用 | 用一个渠道代替另一个 |
| P5 交付 | 只读诊断、安装升级、故障恢复、业务回归与移交 | 按文档能安装、诊断、恢复 | 未测能力写成已经支持 |

关机后续跑、Windows、云端代执行、通用多 Agent、群聊和聊天内确认不在这六段里。

P0 到 P5 的验收顺序不能跳。管理端页面草稿、知识样本和 IM 应用申请可以提前准备，Mock 联通不算该阶段通过。

## 2. 报告这条线怎么长出来

首个业务样例是「知识 + 本地材料 → 报告」。能力按阶段加上去，不在 P0 假装企业知识已经接入。

| 增量 | 阶段 | 报告多了什么 |
|---|---|---|
| 合成材料写入授权目录 | P0 | 四节 Markdown、来源指向本地文件；目录外写入被拒绝 |
| 真实模型生成正文 | P0 | `MiniMax-M3` 流式输出；中断不报成功 |
| 登录后才允许调用 | P1 | 请求走企业网关；密钥留在服务端 |
| 审阅后才落盘 | P2 | 候选差异可拒绝；用户改过的文件恢复时提示冲突 |
| 企业证据进报告 | P3 | 引用文档版本和位置；撤权后读不到旧片段 |
| 同一任务从 IM 续写 | P4 | 飞书或企微的输入进同一任务队列 |
