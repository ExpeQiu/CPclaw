# ADR-006 Harness 与信息管道边界

> 发行更新：0.0.42 已替换本机应用并部署配套云端管道；合成真实模型聊天/文档验收通过。完整开放业务质量仍须另验，见 [发布记录](../verification/unified-harness/发布记录.md)。

日期：2026-11-05。状态：用户已确认；源码迁移已完成，待真实模型及发行验收。依据：用户明确“CPclaw 不参与任何信息处理，做好信息管道”。

## 决策

1. 所有用户任务统一进入 DeepSeek Harness，包括普通聊天、澄清、规划、工具执行和交付；一个 CPclaw 聊天对应一个持久 Harness 会话。
2. CPclaw 不进行意图路由、主题推断、历史语义筛选、摘要/压缩、证据充分性判断、内容续写或业务完成判断，不直接调用 LLM 替代内核。
3. CPclaw 负责原文与资源引用的持久化、有序投递、工具和资源协议适配、权限、预算硬限制、幂等、取消、日志、结果展示及成果存储。结构校验和执行事实不能被当成内容正确性或任务完成证据。
4. 项目目录、知识库及资源可跨聊天按 ACL 共享；聊天消息、内核上下文和执行历史不共享。共享与访问范围不授予跨聊天上下文读取权。
5. 文档、Wiki、经验提炼和语义诊断通过 Harness 发起并处理，宿主不保留平行语义工作流。云端控制面不因此获得员工任务托管能力；未来云端语义资源作业需单独定义 Harness 执行域。
6. 工具授权、凭证保护、企业 ACL 和人工审核继续生效。CPclaw 拒绝越权/超限调用并返回事实，内核决定允许范围内的后续动作。

## 替代关系

本 ADR 替代 ADR-001 第 5 条及 2026-10-24 补充中“聊天模型先 request_service 转交”的目标路由，细化“宿主结果检查”为协议、权限和持久化检查。它也替代历史指南中的宿主研究阈值、主题拼接、自然语言恢复短语映射、合成收尾答复及内核外模型交付设计。

ADR-002 的权限、ADR-003 的浏览器隔离及强制确认等安全控制继续适用；受影响的具体工具封装随迁移调整。既有发布/验收记录保留为历史事实，不据此宣称新边界已实现。
