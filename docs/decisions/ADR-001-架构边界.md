# ADR-001 架构边界

> 状态：已确认  
> 日期：2026-10-21  
> 模板：4（Skill 平台的控制面 / 执行面）  
> 参考：`/Volumes/Lexar/git/06 achieve/skill-platform-core`，决策对照 `/Volumes/Lexar/git/03T/TPD-skill-platform` 的 ADR-004～006  
> 依据：《企业级智能体平台技术方案》V1.9 第 0、2、3 节

> 2026-11-05：按 [ADR-006](ADR-006-Harness与信息管道边界.md) 更新职责边界。全任务进入持久 Harness，CPclaw 仅作信息管道；历史转交链路退出目标设计，实现迁移待验收。

## 背景

企业要的是「云端管资源和权限，员工 PC 上跑任务」。模板 4 的控制面 / 执行面分离适用。参考仓的 Python、LangGraph、Router→Loader→Executor 实树不适用于本项目：推理循环已指定为 DeepSeek Harness。

## 决策

1. **Skill 载体**：企业审核后的 `SKILL.md` 与不可变发布包。能力声明不是权限。员工不能通过对话安装任意 npm/Python 依赖或内核插件。MCP 是获准工具通道，不是另一套 Skill 运行时。
2. **编排**：Harness 负责推理和工具循环。CPclaw 只做原文/事件管道、工具适配、权限、预算硬限制和协议/持久化检查；内容理解、上下文组织及任务完成判断均归 Harness。不引入 LangGraph，也不自研第二套 Agent 循环。
3. **控制面 / 执行面**：分开。云端持有身份、额度、资源 ACL、审核与发布。员工 PC 持有任务、运行、文件操作和产物检查。云端不调度、也不宣布本地任务完成。
4. **记忆**：个人和项目记忆在本机 SQLite，默认不上云。组织记忆和经验经审核后进云端 PostgreSQL，再按权限下发。两端不能互相覆盖。
5. **路由**：采用自然对话入口，所有消息原文进入该聊天绑定的持久 Harness 会话，包括普通问答、澄清、工具任务和交付。取消内核前的聊天模型分流与 request_service 转交决策。工具由 Harness 选择调用，宿主负责目录、schema、授权、执行和回执；显式资源绑定不强制执行。

投递、进程、授权、执行和成果持久化状态以宿主/目标服务回执为准；任务含义、计划与完成声明由 Harness 产生。界面按来源投影事件，不以流结束或落盘成功推断业务任务完成。一个聊天一个内核会话；不同聊天可共享获准资源，不能合并上下文。

## 不采用

| 选项 | 原因 |
|---|---|
| 模板 1 采集管道 | 首期不是多源采集到 BI |
| 模板 2 硬编码专家类 | 能力靠已发布 Skill 与连接器扩展 |
| 模板 3 并行 Swarm | 首期不做通用多 Agent |
| 模板 5 画布 | 桌面是任务工作台，不是节点编排器 |
| 模板 6 作为产品形态 | CLI 只作为驱动本机应用的适配器 |
| 参考仓 Python 执行栈 | 与已确认的 Harness 内核重复 |

## 后果

工程按 TypeScript 模块划分，目录以技术方案第 3.2 节为准。P0-02 再建立仓库骨架。本决策不创建空包，也不把参考仓密钥或实现复制进来。

历史记录（相关转交设计已被 ADR-006 替代）：2026-10-24 用户确认取消模式开关，改为自然对话按需调用应用服务。request_service 只请求转交，不执行本机命令；原有 Harness 继续负责服务工具循环，宿主控制授权、积分和结果验证。CLI/MCP 共用服务入口，不新增第二套 Agent 循环。
