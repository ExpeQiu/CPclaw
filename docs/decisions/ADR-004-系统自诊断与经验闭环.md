# ADR-004 系统自诊断与经验闭环

状态：已实现已注册维护动作的专用授权与本机经验台账。日期：2026-10-28。

用户原则：自诊断具备最高权限，以解决问题、防止再发、沉淀经验为宗旨。

## 决策

1. 自诊断属于CPclaw系统维护入口，应用内授权优先于普通对话的 ask/auto/full 模式。宿主为修复调用颁发 `system-diagnostic` 权限；普通模型工具参数无法颁发该权限，也不改变普通对话的权限。
2. 已注册的维护动作直接执行，避免逐条重复授权。当前覆盖已有任务连接检查、原提交查询、原资源读取/下载与本机预览恢复；自诊断自动续接可恢复的既有任务，不要求用户再点一次续接。需要官方登录交互的流程保留授权入口。
3. 维护执行仍绑定当前账号和对话，遵守操作系统及外部平台的实际权限。生成、积分批准、任意终端、用户目录外写入和其他尚未实现的维护动作不通过该维护通道执行；扩展能力需要实现对应修复器及验证。
4. 完成标准为问题定位、执行修复、回读验证、交付成果、记录剩余阻塞。无法修复时说明具体阻塞，不能仅以“检查完成”作为成功。
5. 每次完成的诊断及服务端修复写入本机 `diagnostic_runs`；经验汇总于 `diagnostic_lessons`。经验按平台/账号隔离，只存问题代码、维护策略、验证状态和防复发规则，不存会话正文、材料或凭据。
6. 未验证的问题标记 observed；实际修复并验证过的策略标记 verified。同一任务重复点击诊断不会增加问题涉及的任务数。后续同类诊断加载已有经验，优先展示验证过的策略；经验不作为任意脚本执行指令。

## 当前边界

本决策没有为自诊断提供操作系统root、缺失的平台凭据或全能代码修复器，也不宣称已经支持自动修改源码、替换APP或修复远端网关。此类能力需要进一步实现和验收，不能通过放开普通对话工具权限代替。
