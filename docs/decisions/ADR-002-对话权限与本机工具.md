# ADR-002 对话权限与 Harness 本机工具

状态：已实现；来源：用户要求参考 Codex 对话鉴权，并明确选择完全访问覆盖本机任意文件与通用终端。

保留 ADR-001 的单一 Harness 推理循环、宿主执行权威与云端账号 ACL。扩展本机执行边界：用户可为当前对话选择请求批准、帮我批准、完全访问三种权限模式。完全访问不局限于已配置应用服务或当前项目，因此取代 ADR-001 中 CLI 仅作为应用驱动适配器的范围限制。

权限只由可信主窗口 IPC 修改，宿主按账号和对话隔离；切换模式增加权限版本、中止当前工具并拒绝旧任务继续调用。模式在当前应用会话有效，账号退出或应用重启后回到默认批准流程。

Harness 通过原有 service_action 接口访问本机文件与终端，并按本轮目录自主切换服务。没有新增 Agent 循环，没有把「模型自称安全」当作批准依据。自动模式依据宿主可识别的读取行为作决定，未知行为询问；完全访问按用户选择直接执行，不声称具备项目沙箱。内置即梦通道继续通过宿主报价和额度授权；通用终端与任意第三方程序的副作用及费用无法被该专用额度完整约束。

对话权限与授权范围是两层：前者决定「是否需要询问」，后者决定「一次批准覆盖多大」。授权范围以用户在授权弹窗内的显式选择为准，不受对话权限模式限制；「请求批准」模式下同样可以一次授权整段任务或整个对话。缺少任务标识时不能选「本次任务」，缺少账号与对话标识时不能选「本次对话」，此时只能单次授权。登录与支付等强制确认场景不因范围选择而放宽。详见 [028 验收](../verification/授权范围解耦028.md)。
