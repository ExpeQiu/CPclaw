# CPclaw 技能市场实施与验收清单

日期：2026-10-26。状态：实施基线，工程进展与未执行的正式验证见 [实现记录](../verification/技能市场功能实现20261026.md)。产品规格见 [技能市场功能设计](技能市场功能设计.md)；本文件不表示相关能力已经交付。

完成口径：以真实资源、当前身份、当前设备和实际产物验证用户流程。页面演示、Mock 回执、写入安装记录不能代替对应真实闭环。

## 1. 实施顺序与工作包

每个工作包交付可运行增量及其验收证据。先统一资源身份，再连接本机生命周期，然后完善使用、创作与运营；内容编制可与不依赖它的工程任务同时准备，无需增加独立技术平台。

### R0：统一契约，保护旧资源

| 编号 | 任务与交付 | 前置 | 完成标准 |
|---|---|---|---|
| M01 | 盘点两套资源模型及调用者，形成映射表与迁移脚本方案 | 无 | 对草稿、个人资源、发布、安装、专家和聊天绑定逐类列出迁移规则 |
| M02 | 定义 Skill / Release / Submission / Install / Binding 契约 | M01 | 稳定 ID、组织边界、摘要、版本唯一性和状态权威位置明确 |
| M03 | 新领域读写及旧接口兼容适配 | M02 | 唯一写路径；旧入口能读取映射资源，不长期双写 |
| M04 | 临时数据库迁移、异常数据和回退预演 | M03 | 数量、摘要、所有权、状态、安装和绑定逐项核对；同名资源不自动合并 |
| M05 | 创建首批技能内容模板及验证样本 | 无 | 每条有用途、输入输出、来源、依赖、例子与维护字段，正式包与演示夹具分离 |

放行：保留现有创建、个人使用、审核、安装和新聊天能力；历史 withdrawn 不自动变成可用；原市场安装标记不伪装成本机安装成功。

### R1：让员工完成第一次实际工作

| 编号 | 任务与交付 | 前置 | 完成标准 |
|---|---|---|---|
| M06 | 目录查询、分类、别名、过滤、分页与排序 | M03 | 权限过滤先于统计；详情正文按需取；无结果与网络失败区分 |
| M07 | 卡片、详情、示例、空态和窄窗口工作区 | M06 | 不读正文也能判断用途、输出与阻碍；返回原聊天不丢输入 |
| M08 | 本机制品安装、摘要与路径校验、进度和恢复 | M02–M04 | 实际文件与指针正确；重复点击幂等；失败保留旧版 |
| M09 | 依赖解析及连接器/应用服务统一状态投影 | M08 | 已安装与待登录/缺工具分开；修复后返回原技能重新检查 |
| M10 | 新聊天及当前对话选用、绑定与解除 | M07–M09 | 固定具体版本；运行时不能静默切换；解绑后保留历史继续聊天 |
| M11 | 输入补齐、上下文预检和统一资源快照 | M10 | 普通问答、文档和服务执行均带正确版本；必填输入不会执行后才发现缺失 |
| M12 | 受控结果检查与实际成果入口 | M11 | 模型称完成但无文件/服务终态时，不能记为检查通过 |
| M13 | 正式精选内容包与员工主路径验收 | M05、M12 | 至少 6 个基础精选技能逐条通过案例；目录非空但不含占位或测试资源 |

放行的三条主路径：

1. 新员工在目录找到“材料报告”，看懂样例，安装、选材料并生成可打开的报告。
2. 已有技能从当前对话选用，缺输入时补齐，完成后解除绑定继续聊天。
3. 应用依赖未就绪时明确卡在具体条件；修复后继续原输入，最终查看真实成果。依赖应用需具备真实测试条件。

现有创作与审核入口在本批持续可用；只完成页面改版不算 R1 交付。

## 2. 现有代码落点与改造边界

| 位置 | 建议职责 | 改造注意 |
|---|---|---|
| packages/contracts/src | 资源、版本、安装操作、依赖与运行引用的类型契约 | 新增业务契约，不暴露 Harness 私有类型 |
| packages/platform/src/market.ts | 目录和创作应用服务 | 拆出稳定实体与权限规则，避免一个 action 函数持续堆积 |
| packages/platform/src/enterprise.ts | 既有发布、提交与审核能力 | 与市场统一领域模型，保留兼容入口，不另造发布表 |
| packages/platform/src/market-page.ts | Web 展示或共享市场视图入口 | 正文与领域逻辑分离；首期可保留 iframe，不以 UI 重写为前置 |
| packages/desktop-host/src/skill-install.ts | 本机固定版本安装及读取 | 复核并完善真实原子切换、故障恢复与版本不可变保护 |
| apps/desktop/chat-service.mjs | 当前绑定读取、草稿生成/提炼与聊天桥接 | 抽出资源准备逻辑，覆盖普通聊天、文档、服务转交全部路径 |
| apps/desktop/extension-host.mjs、extension-service.mjs、service-runtime.mjs | 真实 CLI/MCP 发现、授权、调用和回执 | 市场消费其能力与状态，不复制新的通用执行器 |
| apps/desktop/renderer/market.js | 市场视图、返回与选用上下文 | 与现有聊天、文档和应用面板共存；不要顺带重排其他功能 |
| packages/platform/test/market.test.mjs | 领域权限、生命周期、数据持久化 | 把新旧模型迁移与固定修订纳入验证 |
| scripts/verify-desktop-market.mjs | Electron 用户流程 | 拓展主路径与异常；仍使用隔离数据，不向生产库 seed |

不要求为每个表建立一个新 package。模块拆分以职责和可测试边界为依据，沿用现有工程与生命周期脚本。

## 3. 关键验收用例

| 编号 | 场景与操作 | 预期结果 | 对应工作包 |
|---|---|---|---|
| A01 | 同组织、跨组织及本人草稿分别查询目录与详情 | 只返回有权访问的条目；计数不泄露他人资源 | M03、M06 |
| A02 | 默认目录为空、筛选无命中、平台断网 | 三种不同状态和处理入口；无演示条目混入 | M07、M13 |
| A03 | 用别名搜索并组合筛选，进入详情后返回 | 结果正确；条件、滚动与选中项保留 | M06、M07 |
| A04 | 安装正常包、摘要损坏包、路径异常包 | 正常制品落盘；异常被拒绝，旧版可读取 | M08 |
| A05 | 重复点击安装；下载或指针提交时退出重启 | 一个操作；恢复后状态与文件/指针一致，无半成功 | M08 |

| A10 | 同技能分别用于问答、文档和真实服务请求 | 三种路径均记录同一正确资源快照并受授权约束 | M11 |
| A11 | 输入缺失、材料不可读、知识库无命中 | 执行前补齐或说明限制，不编造材料 | M11、M12 |

| A15 | 固定草稿试用后修改正文/依赖 | 旧证据保留但标为旧修订；提交需对应新修订检查 | M15 |
| A16 | 个人版本提交审核，新版本被退回 | 原个人可用快照与旧发布版本仍可按权限使用 | M16、M17 |
| A17 | 员工越权审批、审核时修改提交、重复批准 | 越权拒绝；不能换掉已审摘要；最多一个发布版本 | M17 |
| A18 | 安装新版失败、成功后旧运行继续、切回旧版 | 失败保留旧版；成功只影响后续选择；合规旧版可切回 | M18 |
| A19 | 常规下架与紧急停用分别作用于已装技能 | 行为符合设计第 11.3 节；历史 withdrawn 不自动放宽 | M19 |
| A20 | 技能失效后解除绑定继续当前聊天 | 保留原记录和产物，后续不再加载新技能指令 | M10、M19 |
| A21 | 专家一个成员安装失败；卸载组合 | 未显示就绪；独立安装及其他组合引用不被删除 | M21、M22 |
| A22 | 成员出新版或紧急停用 | 新版不静默更换组合；停用按策略影响引用 | M21、M22 |
| A23 | 导入同名旧资源及已有聊天、安装与审核记录 | 不按名字误合并，映射可追踪；未知映射提示人工处理 | M04 |
| A24 | 切换账号/退出登录时有检查或授权等待 | 状态隔离；取消旧上下文等待，不能用新账号续做旧操作 | M09、M11 |
| A25 | 窄窗口、键盘打开关闭详情、保存失败离开 | 主要操作可达；焦点恢复；未保存内容有保护 | M07、M14 |
| A26 | 查看反馈、埋点及日志内容 | 能定位版本和阶段；不含凭据或默认上传的私有正文 | M20 |
| A27 | 六个核心官方技能逐条真实执行 | 各有 2 个正常案例、1 个异常案例和可检查的输出 | M13 |
| A28 | 三种对话权限模式下选用/切换/试用技能，执行中降权 | 不扩大或重置模式，不重复已有授权；旧运行不能继续使用已撤销权限 | M10、M11、M15 |

部分用例可用隔离服务或故障注入验证确定性逻辑；真实依赖的就绪、业务效果和内容上架需补真实证据。Mock 通过不写成真实第三方接入完成。

## 4. 验证证据与交付门槛

每批验收保留：

1. 变更范围与兼容说明，包含资源模型或权限变化。
2. 对应自动化结果与必要的 Electron 主路径截图。
3. 实际验证环境、应用/模型/Harness/技能版本和时间。
4. 产物或回执引用、异常恢复结果及未支持项。
5. 与本清单用例的映射，失败项及处理决定。

实施时按改动范围运行构建、平台/宿主相关测试和市场 Electron 流程；其他模块被实际改动时再补相应回归。现有验证命令可复用，但不能把历史测试数量或旧截图作为本批通过依据。

三类“完成”必须分别报告：

- 工程完成：契约、迁移、安装、权限和执行链路经验证。
- 内容完成：真实官方技能及样例已审核发布，目录里能找到并使用。
- 产品验收：目标员工在实际环境独立完成任务，已知限制已记录。
