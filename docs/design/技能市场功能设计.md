# CPclaw 企业技能市场功能设计

日期：2026-10-26。状态：功能设计基线；工程进展见 [实现与验证记录](../verification/技能市场功能实现20261026.md)。本文件中的规划、候选内容与指标不代表已上线或通过正式业务验收。

用户已确认定位：**企业内部市场：官方精选 + 员工创作 + 组织审核共享。**

## 1. 完成标准与核心判断

本轮交付产品定义、页面与交互、完整用户流程、状态规则、内容供给、数据与接口边界，以及分期实施和验收清单。实施任务见 [技能市场实施与验收清单](技能市场实施与验收清单.md)。

技能市场应让员工回答五个问题：

1. 我想完成的工作，有没有现成方法？
2. 这个技能会交付什么，需要提供什么？
3. 我的电脑、账号和工具现在能不能用？
4. 使用后是否真正完成任务，结果在哪里？
5. 我做成的方法能否再次使用、交给同事，并持续改进？

“有页面、能保存正文、能安装”只完成资源登记。产品完成标准是：**发现 → 理解 → 安装 → 就绪 → 使用 → 检查结果 → 沉淀 → 审核共享 → 更新维护**可连续完成，异常也有恢复入口。

### 1.1 当前实现核对

核对范围为本地 CPclaw 源码和项目说明；本轮未登录线上服务、未读取真实用户目录、未实测当前安装包。仓库中的历史验收记录只作为历史证据。

| 维度 | 当前可确认的实现 | 主要缺口 |
|---|---|---|
| 页面 | 桌面浮层加载平台生成的页面；技能、专家、连接器、创作、管理员审核入口 | 信息层级偏表单；无完整的选型、就绪和使用引导 |
| 目录 | 默认空库；名称和说明的本地关键词过滤 | 没有官方内容供给；分类、任务入口、组合筛选不足 |
| 详情 | 名称、说明、正文、来源链接和组合成员 | 输入输出、样例、依赖、兼容性、验证证据与适用边界未结构化 |
| 安装 | 市场链路在 market_installs 写入账号的安装和启用记录 | 未与本地固定版本制品安装闭环统一；安装不等于依赖就绪 |
| 使用 | 安装启用后创建绑定技能的新聊天；普通聊天路径注入技能正文 | 当前对话选用、解除绑定、版本锁定、预检与结果验证需形成统一契约 |
| 创作 | 手动、AI、文本文件夹/ZIP、登记开源来源；对话提炼为草稿 | 向导、依赖声明、试用反馈、发布前检查不足 |
| 更新 | 已发布正文不可覆盖；另存新版本 | 不同版本缺少稳定的技能身份；需手动安装新版、卸载旧版 |
| 专家 | 管理员选已发布技能，使用时拼接正文 | 缺少任务入口、输入契约、依赖合并、版本锁定及组合验证 |
| 连接器 | 市场存本人 CLI/MCP 配置；应用服务链路另有真实发现与执行 | 配置、检测、授权、实际可调用状态没有在市场统一表达 |
| 发布 | 个人使用、提交、管理员通过/退回/撤回 | 证据、版本差异、目录编辑、撤回影响与通知不足 |
| 数据 | market_items 等市场表，另有 skills / skill_releases / skill_submissions | 两套发布模型并存，不能继续各自扩展 |

当前“个人使用”内容仍保存于平台，现有管理员可见；不能标注为“仅本机”。当前文本上传限制为最多 50 文件、正文合计 100KB，ZIP 压缩包最多 300KB；聊天技能正文合计超过 6000 字会失败。这些限制在改造前仍有效。

### 1.2 依据与边界

- 延续 [ADR-001 架构边界](../decisions/ADR-001-架构边界.md)：平台管理资源与发布，本地宿主管理执行；Harness 承担推理及工具循环。

- 延续原产品设计中的四个入口及“固定版本、依赖检查、运行验收”；原设计位于 [PC 端功能与交互设计](</Users/expeqiu/Documents/ChatGPT/Cclaw/harness/PC端功能与交互设计_WorkBuddy参考.md>) 第 5.6 节。
- 对照 [技能市场现有说明](../../guide/技能市场.md)、[应用服务现有说明](../../guide/拓展应用.md) 和源码判断现状，说明中的不同阶段限制不自动视为同一时点的实际能力。

## 2. 产品定位与范围

市场的核心资源是**可复用、可验证的工作方法**。员工按工作成果找技能，创作者按方法维护内容，管理员按版本审核共享。

| 对象 | 用户理解 | 负责什么 | 不应混淆为 |
|---|---|---|---|
| 技能 | 一种完成工作的办法 | 输入要求、步骤、依赖、输出与验收方法 | 已经授予的工具权限 |
| 场景专家 | 一组围绕某类工作的技能和入口 | 场景说明、成员固定版本、任务模板 | 独立 Agent 或自动并行组织 |
| 连接器 | 使用某个应用或服务的通道 | 实际能力发现、账号状态、工具调用 | 技能本身 |
| 知识库 | 工作时参考的资料 | 检索、来源、版本与访问权限 | 复制进技能就能永久共享的正文 |
| 项目 | 本次工作的材料和成果空间 | 文件、任务、上下文与产物 | 技能市场的另一套资源目录 |

首期范围：

- 官方精选目录、已审核的组织技能、本人技能库。
- 找技能、看样例、安装与更新、依赖处理、用于任务。
- 手动/AI/对话提炼/导入技能，共用同一草稿与检查流程。
- 管理员审核、发布、目录维护、下架和紧急停用。
- CLI/MCP 配置及就绪状态，复用已有应用服务执行通道。

后续范围：部门/项目定向分发、本地未上传草稿、受控开源导入增强、组织授权自学习候选、更多文件处理能力。

本次不建设：交易支付、跨组织公开分发、社交动态、作者粉丝体系、开放脚本商店、通用多 Agent 编排。实际存在的需求再单独立项。

## 3. 用户与核心场景

现有 employee/admin 两种角色足够支撑首期。创作者是员工的一种行为，不增加独立账号类型；内容运营首期由获准管理员承担。

| 场景 | 人群与触发 | 主路径 | 当前阻碍 | 完成判据 | 优先级 |
|---|---|---|---|---|---|
| S01 首次找方法 | 新员工需要一份材料报告 | 搜索成果 → 详情样例 → 安装 → 填材料 → 使用 | 不知道有哪些资源，也不知道交付物 | 用真实可读取材料生成并打开报告，记录技能版本 | P0 |
| S02 重复工作 | 员工再次做相似任务 | 我的技能库 → 最近使用 → 新任务/当前对话 | 只有市场新聊天入口，复用成本高 | 一次选用后进入输入补齐；不丢原对话 | P0 |
| S03 缺少工具 | 选用依赖 CLI/MCP 的技能 | 预检 → 定位缺项 → 配置/登录 → 重新检查 | “安装成功”与“能执行”混淆 | 显示各缺项，修复后才进入对应执行 | P0 |
| S04 沉淀经验 | 员工完成一次有价值工作 | 提炼 → 参数化 → 试用 → 个人可用 | 有草稿，没有验证闭环 | 新输入能再次完成；不固化旧任务 ID/凭据 | P0 |
| S05 共享方法 | 员工希望同事复用 | 提交固定修订 → 管理员验证 → 发布 → 同事使用 | 审核依据和共享内容不清晰 | 同组织第二账号可使用固定版本；草稿不被看到 | P0 |
| S06 维护更新 | 创作者修正一个已发布技能 | 新版草稿 → 差异 → 测试 → 审核 → 用户更新 | 版本彼此孤立，容易重复安装 | 用户能看差异、更新或保留旧版；失败保留旧版 | P0 |
| S07 使用场景专家 | 员工要完成一类岗位工作 | 专家详情 → 选择任务 → 检查组合依赖 → 使用 | 组合只是一份长提示词 | 具体任务有输入输出；成员版本可追溯 | P1 |
| S08 故障与撤回 | 依赖失效、撤权、任务中断 | 查看原因 → 修复/换版本/解绑 → 继续原工作 | 只给报错，可能只能新建聊天 | 保留历史成果，后续动作受实际状态约束 | P0 |

优先级按“是否闭合高频工作 × 是否覆盖多数员工 × 对既有能力的复用程度”排序；不以页面数量或目录条目数量排序。

## 4. 信息架构

保留现有入口，避免再建立一套“发现中心”或“插件中心”。

~~~text
技能市场
├─ 技能
│  ├─ 内置技能：官方维护、经发布的精选资源
│  ├─ 技能广场：本组织审核发布的资源
│  └─ 我的技能库：已安装、个人可用、可更新、需处理
├─ 场景专家
│  ├─ 市场
│  └─ 已安装
├─ 连接器
│  ├─ 我的连接：CLI / MCP
│  └─ 添加连接：获准服务模板 / 手动配置
├─ 技能创作
│  ├─ 新建：AI / 手动 / 对话提炼 / 文件导入 / 开源引入
│  └─ 我的创作：草稿、个人可用、审核中、需修订、已发布
└─ 审核与管理（管理员）
   ├─ 待处理 / 已处理
   ├─ 已发布资源与版本
   └─ 目录编排、分类与精选
~~~

“我的技能库”回答我能用什么；“我的创作”回答我维护什么。个人可用但未安装的技能出现在前者，提供安装入口；草稿只出现在后者。

### 4.1 全局交互规则

- 从快捷栏打开市场为工作区级视图；保留当前聊天、输入草稿、右侧文档或应用状态。关闭或 Escape 返回原工作。
- 切换页签保留各自搜索、筛选、滚动和选中项；返回详情列表不跳回顶部。
- 详情采用宽抽屉或详情页；创作采用完整编辑页，避免同屏堆叠长表单。
- 窄窗口使用单列卡片与全宽详情，始终有明确返回入口；不依赖横向滚动使用。
- 选项卡、弹窗和错误信息支持键盘操作；关闭后恢复原焦点；状态不能只靠颜色区分。
- 安装、保存、提交和使用按钮防重复；较长动作可查看进度，关闭视图不等于取消任务。
- 加载失败保留当前条件和旧数据并提示数据时间；不能显示成“没有技能”。
- 桌面可以安装和执行；Web 端可发现、创作、审核，涉及本机检查或任务时提示在桌面继续。

### 5.1 列表页

~~~text
技能   场景专家   连接器   技能创作                 审核与管理

内置技能 / 技能广场 / 我的技能库
[搜索：你想完成什么工作？                       ] [创建技能 ▾]
工作场景：全部 / 文档报告 / 资料整理 / 产品运营 / 内容创作 / 数据处理
条件：来源 ▾  就绪状态 ▾  安装状态 ▾              排序：推荐 ▾

官方精选（仅展示实际已发布且有权访问的条目）
┌ 材料报告             ┐  ┌ 会议纪要             ┐
│ 从选定资料生成报告   │  │ 整理决策与待办       │
│ 输出：Markdown      │  │ 输出：纪要与行动清单 │
│ 官方 · 1.0.0        │  │ 官方 · 1.0.0        │
│ 就绪/待选材料       │  │ 已安装 · 可直接使用  │
│ [查看详情] [安装]    │  │ [使用]              │
└────────────────────┘  └────────────────────┘
~~~

卡片必显：名称、一句话用途、输出类型、发布者/来源、版本、安装状态，以及阻断使用的首要原因。分类、更新时间、验证标识作为次要信息；文件清单、全部依赖和审核记录进入详情。

分类按工作成果而非技术协议组织。初始建议：文档报告、资料整理、产品与运营、内容创作、数据处理、应用操作；没有资源的分类不占主导航。

搜索首期支持名称、说明、标签、场景、输入输出类型和人工维护的别名；例如“汇报材料”可以匹配“材料报告”。使用现有数据库的索引能力即可，先验证中文子串与别名召回，不先引入向量库。

组合筛选：来源、分类、安装状态、就绪状态、输出类型；专家另支持岗位。筛选与搜索取交集，显示结果数和“清除条件”。权限先过滤，再计算数量和排序。

排序首期提供官方推荐、最近更新、名称；我的库提供最近使用。推荐由管理员配置顺序和场景，不以伪造热度填空。后续有有效使用数据后再提供常用排序。

### 5.2 详情页

| 区域 | 必须回答的问题 | 内容 |
|---|---|---|
| 首屏概览 | 我是否需要它？ | 用途、适用/不适用、作者、版本、状态、主要输出与主操作 |
| 效果与示例 | 实际会得到什么？ | 一份合成输入、一份实际验证过的输出预览、验收说明；示例可直接带入试用 |
| 输入要求 | 我需要准备什么？ | 必填/选填参数、材料格式、项目/知识库选择、目标输出位置 |
| 运行条件 | 我的环境能用吗？ | 应用/工具依赖、登录、兼容环境、能力声明、可能费用、逐项检查结果 |
| 方法说明 | 它如何做？ | 可读步骤、完整 SKILL.md、文件清单；非上传 JSON 大段正文 |
| 版本与验证 | 哪个版本可信？ | 当前/已装版本、更新说明、变更差异、验证环境与日期、已知限制 |
| 来源与维护 | 遇到问题找谁？ | 官方/员工/开源来源、维护者、许可信息、反馈入口、停更说明 |

主操作由当前状态计算，每次只突出一个：安装、查看安装进度、配置依赖、使用、查看更新、修复、查看撤回原因。卸载、导出、复制为草稿等放次级操作。

“官方”表示维护来源；“已审核”表示组织发布通过；“已验证”表示指定版本在指定环境完成过测试；“本机就绪”表示当前设备检查通过。四者独立展示，不能互相替代。

### 5.3 空状态

| 状态 | 展示与下一步 |
|---|---|
| 官方目录未配置 | 员工看到目录尚未发布及创建入口；管理员看到“导入官方内容包”；不自动写入演示条目 |
| 技能广场为空 | 说明只有审核通过资源才展示，提供创建/贡献入口 |
| 我的库为空 | 推荐查看实际官方精选或导入已有技能 |
| 搜索无结果 | 保留关键词，显示清除筛选/换关键词；允许用当前需求创建草稿 |
| 平台不可达 | 明确连接失败，显示缓存时间与重试；不显示零条结果 |
| 没有访问权 | 提示不可访问或资源不存在；不透露其他组织资源标题、数量和正文 |

## 6. 安装、就绪、更新与卸载

### 6.1 把四类状态分开

| 维度 | 状态例子 | 归属 |
|---|---|---|
| 资源发布 | 草稿、个人可用、待审核、退回、已发布、已下架、紧急停用 | 平台，具体版本 |
| 本机安装 | 未安装、下载中、校验中、安装中、已安装、失败 | 员工 + 设备 + 技能版本 |
| 员工设置 | 启用、停用；当前选用版本 | 员工设置，设备实际状态单独投影 |
| 就绪检查 | 检查中、就绪、缺依赖、待登录、不兼容、检查过期、未知 | 当前设备与账号 |

顶部可汇总为“已安装，待登录”等短句，但详情必须能看到组成原因。“可更新”是发布版本与当前版本比较结果，不是安装失败状态。

### 6.2 首次安装

1. 获取有权访问的具体发布版本和经认证的发布清单。
2. 展示此次安装内容、已有依赖、缺失依赖及可能影响。普通技能不增加重复确认；安装外部应用沿用已有授权。
3. 下载到暂存区，校验大小、目录、摘要、发布来源和兼容性。
4. 写入不可变版本目录，完整校验成功后切换安装指针；失败保留旧版和失败原因。
5. 检查当前设备上的应用版本、工具能力、登录及任务所需条件。
6. 显示“已安装，可使用”或“已安装，需完成配置”，并定位到具体处理项。

同一安装请求重复提交返回原 operationId；进度来自真实阶段，无法估算时不显示虚构百分比。下载校验阶段可取消并清理暂存；指针提交阶段完成事务后再反馈，避免半安装状态。

纯文本技能安装不安装 npm/Python 依赖。所需 CLI/MCP 通过获准应用适配器配置；不运行技能包自带的安装后脚本。

### 6.3 就绪面板

每项显示名称、必需/可选、实际状态、检查时间与处理操作：

- 运行环境与 CPclaw/Harness 兼容性。
- 内部能力：项目文件读取、知识检索、文档交付等是否存在。
- 外部依赖：对应服务实例、CLI 版本或 MCP 工具、当前账号、可用性。
- 本次任务材料：缺少输入与目录选择不是“未安装”，进入输入补齐。
- 授权：预检只说明是否需要授权；任务实际执行仍由宿主按既有授权范围判断。

检查结果有时效，绑定账号、设备、连接配置修订和版本。登录变化、配置变化、关键调用失败后失效；未知不得当作就绪。可选依赖失败只影响声明的可选输出。

### 6.4 更新、回退与卸载

- 更新页展示旧/新版本、变更说明、新增依赖、输出变化和不兼容项。首期手动更新，不默认后台热更新。
- 新版准备成功后切换后续运行的默认版本；正在运行的任务固定原版本，安装失败不改变旧指针。
- 旧版仍可访问且依赖兼容时允许切回；紧急停用、权限撤销或不兼容的版本不可回退使用。
- 卸载前列出受影响的专家/会话绑定；正在被运行引用的制品延后清理，取消后续选择不强杀现有外部任务。
- 卸载技能不删除聊天、成果和项目材料，不卸载独立应用或替用户注销账号。
- 常规停用仅阻止新运行选用；当前运行版本与授权照常核验。管理员紧急停用在下一次能力调用前阻断，已有外部请求按实际能力查询或取消。

## 7. 使用技能与检查结果

### 7.1 四个入口，一个执行链路

详情页“使用”、我的技能库、聊天输入框“技能”、自然语言明确选用，最终都创建同一份技能绑定与运行快照。首期每个聊天显式选择一个技能或一个专家组合；不提供任意多选拼接。

默认从市场“使用”创建新聊天；从当前对话选择器进入则应用到当前对话，并展示替换影响。运行中只允许查看，切换或解绑需等待当前运行结束或停止。自然语言匹配到多个技能时让用户选择；未明确选用时只推荐，不静默启用。

### 7.2 输入与执行

1. 固定版本，展示用途与输入要求；任务表单支持文本、明确选中的材料、项目/知识库引用及输出位置。
2. 示例按钮使用合成材料填入输入框；点击后仍由员工发起试用，不自动计费运行。
3. 校验必填输入、材料是否可读、依赖与访问权，缺项原位补齐；保留已填内容。
4. 输入框上方显示“技能名 · 版本”和所用资料；可看详情、替换或解除。
5. 普通问答、文档生成和 CLI/MCP 服务转交共用该绑定快照；不能某条分支加载、另一条分支遗漏。
6. 技能方法按需加载到现有 Harness/聊天通道；实际工具调用继续经过宿主和已有服务适配器。
7. 展示实际阶段、等待授权、完成或失败，并在结果中显示可打开的产物与检查结论。

不会在首次安装时把某次任务的项目目录或第三方授权永久写入技能。重复使用可记住非敏感参数，材料及访问权仍按当前任务核对。

安装、更新、试用或切换技能均不切换对话权限模式，不复制其他对话的授权；有效授权继续复用，不重复索取。运行记录关联权限修订，但执行时仍核对当前权限，旧快照不能绕过用户降权或撤销。完全访问模式下的通用本机工具继续按 ADR-002 工作；市场只负责发布包和依赖说明，不另加一套工具审批。

### 7.3 结果验证

| 输出类型 | 最小检查 |
|---|---|
| 结构化文本 | 必需章节/字段存在；缺失材料或未证实结论有明确标识 |
| 项目/知识报告 | 实际使用的来源可追溯；引用有文档与位置；无材料时不冒充完成 |
| 本地文件 | 实际文件存在、可读取、类型符合声明，输出位置正确 |
| 应用操作 | 获取服务真实回执及终态；已提交/受理不等于完成 |
| 图片等媒体 | 沿用已有下载与文件检查，区分在线可查看与本地保存成功 |

技能定义“要检查什么”，检查器来自受控宿主或现有验证模块，不执行上传的任意验证脚本。模型自评只作为辅助，不能代替文件或服务事实。

结果卡显示：技能与版本、完成情况、成果入口、验证结论、实际可得的耗时/用量、反馈与“提炼成技能”。没有可靠费用时显示“未知/待结算”，不把未知记为零。

### 7.4 中断、解绑与上下文

- 失败保留输入、运行身份和已有产物；支持修复条件后明确继续。外部提交状态未知时查询原任务，不重跑新任务。
- 技能失效时解释具体原因，提供配置、换可用版本、解除后继续普通聊天；不要求丢弃历史。
- 解除技能只影响后续运行，不删除历史指令、成果或审计；界面说明历史内容仍存在，不承诺彻底抹除模型记忆。
- 继续既有聊天时按已选版本启动新运行并复核有效性，不静默升级；用户选择新版才改变后续快照。
- 6000 字现有限制先在创作检查和选用前明确提示。后续支持短入口 + 按需读取 references；必须保留约束，不能用静默截断规避限制。

## 8. 技能创作：从表单变为可验证的方法

### 8.1 创建入口与统一流程

~~~text
选择来源 → 定义用途与输入输出 → 编辑方法和依赖 → 检查 → 试用
                                                       ↓
                              保存个人可用 / 提交组织审核
~~~

| 来源 | 交互 | 输出与限制 |
|---|---|---|
| AI 创建 | 描述想完成的工作、样例输出、可用工具；缺少关键条件时追问 | 生成结构化草稿，未知依赖标为待确认；不把生成当验证 |
| 手动创建 | 用途、输入、步骤、输出、依赖等分区编辑；保留 Markdown 模式 | 同步预览与检查，不强迫创作者先填写技术字段 |
| 从对话提炼 | 延续回复操作；选择本轮或明确选中的步骤、修正、回执 | 展示材料范围，参数化历史 ID/路径；无回执标记未执行验证 |
| 文件夹 / ZIP | 预览文件树、入口、大小、忽略项和逐条错误 | 沿用文本限制；仅接收有用文件，不上传整个项目 |
| 开源引入 | 来源、固定 tag/commit、维护者、许可、引入理由、依赖 | 首期登记并导入用户选定文本包；后续获准抓取也只生成候选，不自动执行 |
| 从已有技能复制 | 说明“基于某技能的个人副本”，保留来源版本 | 独立维护与送审；不能冒充原作者或覆盖原发布 |

“选择个人知识资料生成技能”作为 P1：显示哪些片段将进入模型和草稿；默认提炼方法、保留引用，不把整份资料复制进组织技能。未经授权的资料不得因提交草稿扩大共享范围。

### 8.2 编辑器内容

- 基本信息：名称、一句话用途、分类、维护者、适用/不适用、来源与许可。
- 输入：参数名、中文标签、类型、必填、说明、默认值、合成样例；材料选取使用现有项目/知识库控件。
- 方法：触发条件、步骤、异常处理；SKILL.md 仍是可导出的主体。
- 输出：结果类型、必要字段/章节、产物要求、检查方式。
- 依赖：内部能力或服务能力、必需/可选、最低版本及可替代项。
- 使用说明：副作用、是否可能付费、授权点、已知限制。
- 发布资料：版本号、更新说明、示例、试用证据、目标范围。

编辑器把业务表单保存为平台发布元数据，并生成/校验 SKILL.md。平台元数据与 Skill 标准字段分开，避免重复维护互相冲突的正文与清单。

草稿自动保存须显示“保存中/已保存/失败”和修订号；离开时仍有未保存内容则提示。并发编辑按 revision 检测冲突，保留双方版本，不静默覆盖。P0 可先采用显式保存和离开保护，自动保存进入 P1。

### 8.3 检查与试用

检查分层显示，不用一个“通过”掩盖不同结论：

1. 结构：入口、文件类型/大小、必要元数据、输入输出声明。
2. 内容：明显凭据/固定实例 ID、遗漏字段、许可资料、上下文长度；机器检查无法保证彻底识别，需人工审阅。
3. 依赖：声明的应用或工具是否存在、是否与当前环境兼容。
4. 试用：以固定草稿修订、合成输入进入现有聊天和宿主执行链路。
5. 输出：结构检查、真实产物或工具回执、作者人工评价。

个人试用只对作者开放，使用明确的草稿快照；权限、执行确认和费用规则与正式使用一致。打开试用不自动提交任务，试用失败回到原草稿并保留反馈。

每次试用记录输入模板版本、草稿/制品摘要、环境、实际状态、检查结果和证据引用。修改正文、依赖或检查规则后旧记录显示“对应旧修订，需重测”。

个人可用不要求组织审核，但仍须结构合法、依赖可解释、执行权限有效。提交共享至少包含适用范围、输入输出、来源、检查结果及有效试用证据；无法在当前设备完成的测试明确为未验证，不允许标注已验证。

### 8.4 创作生命周期

~~~text
草稿 → 检查/试用 → 个人可用快照
  └────────────→ 提交固定修订 → 待审核 → 已发布版本
                                      └→ 需修订 → 新修订重测重提
待审核 → 作者撤销提交 → 保留草稿
已发布 → 创建下一版本草稿（原版继续存在）
已发布 → 常规下架 / 紧急停用
~~~

个人可用快照、待审核快照和已发布快照分别记录，不能只用一个 status 覆盖：提交审核不应让作者原本可用的个人版本失效；新版被退回也不影响旧的已发布版本。

作者可删除未被安装/运行引用的草稿；已发布版本只允许下架或停用，保留追溯信息。已被引用的个人快照采用归档，不删除运行所需内容。

## 9. 场景专家

专家由管理员维护，首期仍是技能组合，不引入新 Agent 运行时。

详情必须包含：适合谁、能完成的具体任务、每个任务需要什么、成员技能及固定版本、合并依赖、输出样例、整体就绪状态。

例如“产品工作助手”可提供“梳理需求”“检查需求文档”“制作验收清单”三个入口。用户先选任务，再准备材料；只加载该任务需要的技能，避免把全部正文无差别拼接。

组合规则：

- 发布专家时锁定所有成员版本，禁止引用草稿、已下架或紧急停用的新安装版本。
- 对成员方法冲突、输入输出衔接、合并依赖和总上下文做组合检查。
- 本机安装事务展示已有、待装、失败成员；全部必需成员可用才标记专家就绪，部分成功明确显示。
- 用户独立安装与组合引用分别记账；卸载专家仅移除该组合引用，保留用户主动安装或其他组合需要的制品。
- 成员新版不自动改变专家；管理员更新组合并重新验证、发布新专家版本。
- 成员紧急停用会阻断引用它的专家；常规下架按固定旧版策略处理，不一律破坏已有运行。

首期建议只做“办公材料助手”“产品工作助手”两个候选专家，在成员技能稳定后上线；不先填满工程、人力、财务、法务等岗位名称。

## 10. 连接器与应用服务

连接器页是配置与检查入口；“拓展/应用服务”是任务中的选择和操作入口。两者共用服务实例与状态源，不维护两套独立配置。

| 区域 | 功能 |
|---|---|
| 我的连接 | 名称、CLI/MCP、启用、关联账号、上次检查、能力数量、被哪些技能依赖 |
| 添加连接 | 获准服务模板或手动配置；展示受支持环境与安装/授权说明 |
| 配置详情 | 地址/程序位置、必要设置、版本与认证状态；凭据通过受控机制处理 |
| 检查结果 | 分别显示程序/服务可达、协议与工具发现、认证、业务所需能力 |
| 关联技能 | 哪些技能依赖该能力，哪些因当前问题不可用 |

CLI 的程序存在、版本检查、能力发现、账号可用是不同事实。MCP initialize、tools/list、权限及 tools/call 成功也分开记录；握手成功不能表示业务操作已授权。

依赖绑定应为“所需服务能力 → 当前用户的服务实例”，例如需要画布生成能力，而非把创作者本机绝对路径写入公共技能。多个匹配实例让员工选择；无匹配进入配置。

启用、保存、检测失败、待登录、协议不兼容、缺业务权限、就绪分别展示。依赖页支持“前往配置并返回原技能”；修复完成后重新检查，保留原输入。

现有真实 CLI/MCP 业务执行通道继续复用；通用 OAuth、更多服务模板和应用安装不因新增市场页面而自动具备，按单项接入验收。

禁用/移除连接器前显示受影响技能和活动运行；后续调用不可用时明确失败，不偷偷切到其他账号或服务。普通配置检查不触发写业务数据或付费生成。

## 11. 审核、发布与运营

### 11.1 首期权限

| 操作 | 员工/创作者 | 管理员 |
|---|---|---|
| 浏览与安装 | 当前组织有权访问的发布资源、本人个人快照 | 按同样规则使用 |
| 编辑、试用 | 本人草稿/副本 | 自己维护的内容；不无痕覆盖他人草稿 |
| 提交与撤销提交 | 本人的固定修订 | 同左 |
| 审核与发布 | 不可 | 对本组织提交进行审核、指定范围 |
| 官方精选与组合 | 不可设置官方身份 | 配置受控官方内容、组合与排序 |
| 下架与停用 | 可申请，个人资源可自行停用 | 组织资源下架、紧急停用、指定替代版 |

首期共享范围为组织；未来部门/项目定向分发需要真正的成员关系和资源 ACL 后再开启。不能先摆可点击但不生效的范围选项。

现状管理员能看到个人草稿。产品建议收敛为默认处理已提交材料，排障访问私有草稿须有明确权限和审计；该调整需与组织管理规则确认，未实现前如实显示保存位置与管理员可见性。

### 11.2 审核工作台

列表显示：名称、作者、版本、提交时间、变更类型、检查/试用结果、待处理时长。详情显示固定提交修订、来源与许可、正文和依赖差异、输出样例、验证记录、建议共享范围及历史意见。

管理员逐项检查“用途可理解、输入输出清楚、依赖真实、例子可复现、无不应共享材料、权限与副作用合理”。通过形成不可变发布版本；退回必须填可执行意见；审核中不得被作者修改同一提交。

审核结论绑定 submissionRevision 和制品摘要；重复点击不会发布两次。作者后续修改生成新修订，旧审核不继承。显示实际处理进度，预计时长仅采用组织配置，不承诺固定天数。

管理员本人发布官方内容也需留下检查、验证和发布记录。首期不强行增加第二名审核员；是否双人复核为组织规则选择，未选择前不扩展角色系统。

### 11.3 下架、紧急停用与通知

| 动作 | 新安装/新选用 | 已安装的固定旧版 | 当前运行 |
|---|---|---|---|
| 常规下架 | 从推荐及默认目录移除，阻止新安装 | 详情保留原因；权限仍有效时允许既有绑定继续 | 不因目录下架中断 |
| 紧急停用 | 阻止 | 禁止新运行 | 下一次受控调用前复核并阻止；已发外部请求按实际能力处理 |
| 撤销员工/组织访问权 | 阻止，缓存不可再授权 | 阻止 | 同上；无法承诺收回已导出副本 |

现有 withdrawn 是统一阻断，实施时须显式迁移为保守的紧急停用语义；不能把历史撤回自动放宽为“仍可使用”。

应用内通知覆盖审核结果、可更新、紧急停用和依赖失效，合并重复事件并提供直达操作。普通使用不弹出无关运营消息；无授权不发送邮件或 IM。

### 11.4 目录运营

管理端提供分类、官方精选、场景集合、排序、维护人、停更标记。选中资源必须已发布、可见且有有效版本。移除精选不等于停用资源。

每个官方技能要有维护人、验证环境、最近验证日期、样例及已知限制。版本或依赖发生变化时进入待回归列表；过期验证显示具体日期，不永久悬挂“已验证”。

反馈首期采用“有用/遇到问题”与问题分类，可附运行引用；默认不上传聊天正文。先解决失败原因与维护闭环，不做评分、评论社区和虚构下载量。

## 12. 首批内容与冷启动

建议准备 8 个候选，先发布至少 6 个依赖现有基础能力的精选技能。每条必须以明确版本、真实样例和验证记录入库；以下名称只是拟建内容，不表示已经存在。

| 候选技能 | 输入 → 输出 | 依赖/限制 | 上架验收 |
|---|---|---|---|
| 材料报告 | 选定材料与问题 → 带来源的 Markdown 报告 | 已有项目/文档通道；材料要可读取 | 报告可打开、章节齐全、引用指向实际材料 |
| 会议纪要与行动项 | 明确粘贴/选定的会议文本 → 决策、待办、待确认项 | 不包含语音转写承诺 | 不编造参会者和负责人，缺失内容标为待确认 |
| 文档摘要与证据提取 | 选定正文 → 摘要、证据、未知项 | 首期支持实际可读文本 | 结论可定位来源，不把推断写成事实 |
| 产品需求梳理 | 需求描述及材料 → 用户、场景、边界、验收条目 | 文本与文档交付 | 缺失条件被列出，验收条目能判定 |
| 方案比较 | 选定方案与比较标准 → 对比表、取舍、缺口 | 使用明确提供的材料 | 每项比较有依据，不虚构参数和价格 |
| 工作周报整理 | 员工明确提供的记录 → 进展、问题、下周计划 | 不自动读取所有聊天或工作活动 | 无来源的成果不计入完成项 |
| 知识库问答与引用 | 问题 + 获准知识库 → 回答与来源 | 真实知识索引、账号权限 | 无命中明确提示，撤权后不能读取旧缓存正文 |
| 即梦海报创作 | 文案、比例、风格 → 实际图片与画布 | 已接入 CLI、登录及实际积分授权 | 真实生成、查询终态、读取下载文件并预览 |

前 6 项是首发核心候选；后 2 项需对应服务与样本完成真实验收，可分批上架。不能因为后 2 项未通过而用占位卡宣称可用。

Word/Excel/PPT、PDF/OCR、联网搜索、浏览器自动化和股票数据等可进入后续需求池。必须接通实际处理器/数据源并验证输出格式后再上架；Markdown 产物不得标为原生 Office 文件。

每个技能的内容交付包包括：用途、SKILL.md、发布元数据、合成输入、实际样例输出、至少两个正常案例和一个异常案例、维护者与版本记录。UI 演示夹具与正式内容包分离。

不在服务启动时自动 seed 生产库。维护者通过明确的“导入官方内容包 → 检查 → 审核发布”动作完成冷启动；演示数据只存在于隔离测试环境。

## 13. 数据、接口与执行边界

### 13.1 统一数据模型

逻辑 Skill、不可变版本、安装状态、任务绑定不能继续混在一行 JSON 中。

| 对象 | 关键字段 | 权威位置与说明 |
|---|---|---|
| SkillDefinition | orgId、skillId、kind、owner、title、category、tags | 平台；kind 为 skill/expert；稳定身份不依赖名称 |
| SkillDraft | draftId、skillId、revision、metadata、content、origin | 平台，明确当前保存和访问规则；本地草稿后续单独做 |
| SkillRelease | releaseId、skillId、version、manifest、digest、status、publishedAt | 平台；唯一约束 orgId + skillId + version |
| SkillSubmission | submissionId、draftRevision、digest、reviewState、note | 平台；审核固定快照 |
| SkillExample / ValidationRecord | release/draft 摘要、inputRef、outputRef、environment、result、time | 平台仅保存获准证据；个人试用正文默认留本地 |
| ExpertMember | expertReleaseId、memberReleaseId、taskTemplateId | 平台；锁定具体成员，不能指向随时变化的 latest |
| SkillPreference | employeeId、skillId、enabled、preferredRelease | 平台或现有账号配置；只表达偏好，不证明某设备安装成功 |
| LocalSkillInstall | accountScope、deviceId、releaseId、digest、path、operationState | 本地宿主；跨设备各自报告真实安装状态 |
| ServiceInstance | instanceId、owner、deviceScope、type、configRevision | 复用连接器/应用服务配置；凭据不在技能或清单中 |
| DependencyCheck | releaseId、instanceId、configRevision、environment、checkedAt、result | 本地事实；平台只能保存必要状态摘要 |
| SkillBinding / RunResourceSnapshot | chatId、runId、releaseId、members、inputRef、dependencyBindings、permissionRevision | 本地；固定资源版本与引用，权限按当前修订复核 |
| Feedback / AuditEvent | subjectId、runRef、reason、actor、time | 最小元数据，不默认上传私有对话和文件正文 |

个人可用也形成不可变快照，来源标记 personal；与公开发布分开。技能依赖声明和运行输入分别建模，不把每台电脑的路径、登录或授权写进公共发布包。

### 13.2 发布清单

沿用原技术方案的发布清单概念，不自建执行 DSL。以下为平台契约草案，不冒充 Harness 原生字段：

~~~yaml
schemaVersion: 1
skillId: material-report
version: 1.0.0
entry: SKILL.md
kind: skill
platforms: [darwin-arm64]
runtimeCompatibility: "<已验证的 CPclaw/Harness 基线>"
capabilities: [project.read, document.write]
requires: []                  # 服务能力依赖；不填作者电脑的路径
inputSchemaRef: input-schema.json
outputContractRef: output-contract.json
packageSha256: "<由服务端计算并绑定发布身份>"
~~~

清单、文件和元数据在发布时一致校验；平台签发的版本记录及认证链确定发布来源，不能只相信包内自报 hash。首期仍为受支持的文本资源，不增加任意执行脚本格式。

### 13.3 职责与数据流

~~~mermaid
flowchart LR
    U[员工：发现和选用] --> C[平台目录与权限]
    A[创作者：编辑和试用] --> S[固定修订与审核]
    S --> R[不可变发布版本]
    C --> R
    R --> I[本地安装与依赖检查]
    I --> B[聊天绑定与运行快照]
    B --> H[现有 Harness 与聊天执行通道]
    H --> T[宿主：授权及 CLI/MCP/文件工具]
    T --> V[真实回执与结果检查]
    V --> O[产物、反馈与方法提炼]
    O --> A
~~~

仍使用现有平台、SQLite、本地工作区和进程边界。首次扩展不引入新的微服务、队列集群、向量库或第二套 Agent 循环。

市场 UI 可以先保留现有 iframe 容器，但应把页面渲染与领域命令拆开。桌面/Web 共享展示语义和接口契约；只有桌面宿主能宣布本机安装、授权和任务实际完成。

### 13.4 命令边界

| 通道 | 建议命令组 | 关键返回 |
|---|---|---|
| 平台目录 | catalog.list / detail / versions / examples | 已按权限过滤的数据、游标、版本与摘要 |
| 草稿 | draft.create / save / validate / snapshot | revision、字段级错误、固定快照 |
| 审核发布 | submission.create / cancel / review；release.withdraw / disable | 被审核的摘要、状态与影响范围 |
| 本地生命周期 | skill.install / update / selectVersion / uninstall / check | operationId、阶段、旧/新版本、真实失败原因 |
| 使用 | skill.bind / unbind / prepareUse | chatId、绑定版本、缺失输入、依赖检查 |
| 执行结果 | run.resourceSnapshot / validation / feedback | 现有运行身份及检查证据引用 |
| 服务 | service.list / configure / inspect / authorize | 复用现有应用通道，不新增市场专用执行器 |

命名是逻辑契约，可通过现有 POST /v1/market 与 workspace IPC 渐进承载，不要求立即新增所有 URL。平台 list/detail 分离，目录不返回所有技能完整正文、草稿或连接器配置；本机操作不伪装成平台 action。

分页、字段校验、服务端权限检查、幂等键和 revision 冲突是契约的一部分。错误至少区分无权访问、版本停用、输入缺失、依赖缺失、待登录、不兼容、制品损坏、保存冲突和外部状态未知，并返回可采取的下一步。

### 13.5 从两套现有模型迁移

1. 盘点 market_items、market_installs、market_connectors 与 skills、skill_releases、skill_submissions 的真实关联和使用者，制作备份与迁移预演。
2. 以稳定 Skill + Release + Submission 为唯一领域模型，扩展现有表或迁移到对应结构；不用新建第三套发布模型。
3. 为每个旧 item 建立 legacyItemId → skillId/releaseId 映射。名称相同不等于同一技能；无法可靠关联的旧版本先独立保留，允许维护者确认后关联。
4. 现有市场安装记录只能迁为“待本机校验/待安装”，不能当成本地已有制品。
5. 聊天旧 item 绑定映射到具体快照；无法映射时保留历史并提示重新选择，不按标题猜测。
6. 原安装模块可复用，但需复核路径校验、不可变版本保护、指针切换与故障恢复；不能只依据注释认定原子性已经满足。
7. 通过兼容适配层保留旧调用一段迁移窗口，迁移后唯一写入新领域模型，避免长期双写。
8. 在测试数据库检查总数、所有权、摘要、审核、安装和聊天绑定；回退先恢复兼容读写路径，不覆盖迁移后产生的新业务数据。

## 14. 非功能与故障体验

- 权限：目录、详情、下载、更新、试用、运行分别检查当前身份；隐藏按钮不替代服务端与宿主校验。
- 来源和数据：共享前展示实际包含的文件/内容；知识引用继续检查源权限，技能发布不复制授权。
- 离线：可浏览已缓存目录和本机说明，显示缓存时间；依赖平台模型与当前权限的任务须在线。安装缓存不是离线执行授权。
- 恢复：客户端重启后安装操作检查暂存和已提交指针，不能把半成品当成功；业务任务按原 ID 恢复查询。
- 并发：同一技能的安装/更新串行；不同设备各自反映状态；首期沿用现有单活动执行槽。
- 可观测：按 traceId、scenarioId、skillId、releaseId、operationId/runId 贯穿发现、安装、依赖、使用与反馈，错误可归因到阶段。
- 隐私：默认只统计最小事件元数据；不因市场统计上传提示词、知识正文、文件内容、第三方凭据或完整工具参数。
- 响应：搜索输入防抖；详情和正文按需加载。列表慢与执行慢分别定位，不把网络等待伪装成技能空目录。

常见异常必须具备直接处理入口：平台连接失败→重试；无搜索结果→清除条件；依赖缺失→配置；待登录→授权；新版失败→保留旧版；草稿冲突→比较修订；资源失效→换版或解绑；产物检查失败→显示已完成和未完成部分。

## 15. 分期、成功指标与验收

具体工程任务、依赖与用例见 [实施与验收清单](技能市场实施与验收清单.md)。不以未提供的人力、预算和业务样本推算上线日期。

| 批次 | 用户可感知的交付 | 放行门槛 |
|---|---|---|
| R0 契约与迁移准备 | 统一技能/版本/安装/运行的定义，确定首批内容 | 迁移预演不丢旧资源、权限或聊天绑定；状态可解释 |
| R1 找得到、装得好、用得成 | 发现/详情/真实安装/就绪/输入/使用/结果闭环 | 至少 6 个核心精选技能有真实证据，三条员工主路径通过 |
| R2 创作与组织共享 | 检查/试用/个人快照/审核/更新回退/反馈 | 两账号完成贡献复用，新版失败与撤回场景通过 |
| R3 场景复用与运营 | 两个专家、组合依赖、精选维护、定向分发候选 | 组合可用且可追溯；只有真实 ACL 就绪才开放定向范围 |

R1 仍保留现有创作和审核能力，并适配统一模型；R2 才完善试用证据、版本维护和运营体验，不能以分期为由破坏已有共享链路。

建议验收方法：

- 工程确定性门槛：必测的权限/版本/安装恢复/不重复外部提交用例全部通过；每个上架技能有对应环境和样例，不能用数量代替质量。
- 体验试点：邀请实际目标员工，测量找到合适技能、准备输入、获得可用结果的过程；记录失败原因，不把教学演示算独立完成。
- 业务样本、试点人数及负责人确认前，不声称转化率、节省时间或满意度已经达标。

建议采集但尚无基线的指标：

| 指标 | 口径与用途 |
|---|---|
| 首次有效使用率 | 首次安装员工中完成首个经检查任务的人数；识别安装后的断点 |
| 安装成功率 | 实际制品提交成功 / 有效安装操作；就绪率另算 |
| 就绪处理成功率 | 曾因必需依赖受阻、后修复就绪的使用准备数 / 依赖受阻数 |
| 任务检查通过率 | 完成必要输出检查的运行 / 已进入执行的运行；区分取消与外部未知 |
| 二次复用率 | 首次完成后在观察期再次完成同技能任务的员工比例 |
| 贡献复用率 | 已发布员工技能中被其他员工有效使用的比例 |
| 更新质量 | 更新后的错误、回退及依赖问题；按具体版本统计 |
| 维护及时性 | 待审核、反馈和待回归条目的处理时长；按实际规则评估 |

事件建议：catalog_search、skill_detail_view、install_started/completed/failed、dependency_blocked/resolved、use_prepared、run_started、result_checked、draft_created、trial_completed、submission_reviewed、release_updated、feedback_created。搜索原文和输入正文默认不进入统计事件。

### 15.1 本轮设计自检

- 覆盖普通员工、创作者和管理员；主场景、异常和维护路径均有下一步。
- 延续四个入口、企业审核及现有本地执行架构；没有新增公共交易或独立执行内核。
- 已实现、设计提案、内容候选、待验证能力明确区分。
- 安装、启用、就绪、权限、审核和任务完成不再混成一个状态。
- 每批有可检查结果；真实环境、正式内容、试点指标不能由 Mock 代替。

## 16. 仍需在实施前收敛的事项

已确认企业内部市场方向；以下只影响对应实施项，不阻断现有产品设计：

| 事项 | 当前建议 | 最晚决策点 |
|---|---|---|
| 首批官方内容维护者与业务样本 | 先做表中 6 个基础技能；项目负责人验收 | R1 正式内容发布前 |
| 组织管理员对个人草稿的可见规则 | 默认只审提交材料，排障访问单独留痕 | 草稿权限改造前 |
| 常规下架与紧急停用治理规则 | 按第 11.3 节区分；历史撤回保守迁移 | R0 状态迁移前 |
| 组织目录是否需要部门/项目分发 | 首期组织级；需要时增加真实 ACL | R3 定向分发前 |
| 试点质量、时延、成本与保留期限 | 先测现状，再设置负责人认可的门槛 | 试点放行前 |
| 开源来源、许可与远程抓取范围 | 首期手动导入文本候选；不默认抓取或安装 | 开源增强功能前 |
