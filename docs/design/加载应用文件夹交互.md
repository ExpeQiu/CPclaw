# 加载应用文件夹交互

日期：2026-11-05。范围：拓展 → 驱动应用，统一已有文件夹添加与 TPCstore 连接入口。源码实现，安装版另行交付。

用户不再先判断应用类型或填写端口。主操作“加载应用文件夹”打开文件夹选择器；静态识别后在弹窗右侧展示名称、来源、用途和下一步。次操作“最近的 TPCstore”复用已保存来源；地址填写放入“手动配置工作台”。

## 识别与下一步

| 文件夹 | 展示与动作 |
| --- | --- |
| TPCstore 根目录 | “检查并查看应用”，授权目录检查后列出应用卡片；已添加项显示“重新连接并打开” |
| TPCstore 内已登记应用目录 | 自动找到所属来源和清单，显示名称与“连接并打开”；无需重新选择根目录 |
| 普通项目 | 明确没有可连接清单，提供“作为项目添加并打开”；不启动未知服务 |
| 独立 app-manifest.json | 识别并说明当前需要 TPCstore 登记及宿主适配；不假装已支持独立插件加载 |
| 损坏清单、重复登记、越界或未知协议 | 保留错误与更换文件夹入口，不静默降级普通项目 |

文件夹识别只读数据，不执行选中源码。真正检查和连接复用宿主确认流程。选择与下一步之间由宿主保留账号绑定的临时选择凭据，过期/账号变化必须重选；不能通过伪造普通项目请求绕过已识别应用的校验。

## 状态与操作

选择中 → 已识别 → 检查/连接中 → 就绪。取消执行保留识别结果，可继续；错误保留原卡片和重试入口，不关闭弹窗。连接中禁用重复操作、分类切换和关闭，明确显示等待；不把启动等待假装成可安全取消的任务。原生执行确认取消后不会启动服务。

成功后复用既有条目、刷新服务列表、绑定当前对话并打开右侧工作台。若当前对话正在执行，保留已添加服务和“打开应用”操作，提示结束当前任务后再打开；无需重连。普通项目也使用同一对话绑定入口。手动配置作为兼容入口保留。

## 验收

真实 Electron 验证选择 CutPot 子目录、原生取消→重试、注入连接错误→重试、真实自动连接、重复加载复用、TPCstore 目录发现、普通项目添加、应用拒绝绕过普通项目入口。继承同一工程双向回读、独立页面和 2 秒本地视频导出检查。

静态测试覆盖损坏/重复/未知协议、相对/文件路径和越界；测试文件夹的 CLI 含抛错脚本，识别仍成功，证明识别不执行源码。完整独立插件加载、其他应用连接、真实模型自主操作和安装版均不在本轮验收范围。
