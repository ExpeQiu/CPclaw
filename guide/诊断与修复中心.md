# 诊断与修复中心

范围：设置页诊断区域统一检查 APP、工作进程、Harness、系统命令路径与当前对话；复用已有对话修复入口，提供固定快捷操作。导出/上传包只含环境状态、诊断结果、近期脱敏日志与对话执行元数据，不含正文、工具参数、账号凭证或模型密钥。

验收：
1. 检查结果按 APP/工作进程/内核展示，检查完成不能等同修复完成。
2. 修复运行环境前检查活动任务；有任务时拒绝重启。修复后重新请求工作进程并检查内核，保留真实验证状态。
3. 快捷操作复用固定宿主动作，不接受任意终端命令。
4. 诊断包可定位本机文件；上传只使用当前登录账号和当前平台，按内容哈希重试同一上传，只有云端 available 与哈希一致才显示成功。
5. 云端回执/包内容只能由所属账号查询；非法形状、超限与疑似未脱敏凭证被拒绝。
6. 界面、宿主 IPC、工作进程与云端接口分别验证；本地通过不冒充生产发布。

## 统一内核边界（2026-11-05 源码）

自诊断直接显示内核可用性、请求状态、配额、工具回执、文件完整性等结构化事实。恢复已有文件只修复存储与预览入口，不改写助手原文，不把局部成果交付认定为全部任务完成。

点击「由内核解释诊断」后，诊断证据作为显式输入交给当前聊天的同一个 Harness 会话；解释、归因和修复建议由内核生成。原始执行记录可通过 execution 资源读取。尚未受理的输入才可补投，已受理或受理不明的输入不整轮重放。

本次仅改源码及验证，以下发布记录不代表本轮改造已上线。

## 云端接口

- `POST /v1/diagnostics`：传入脱敏诊断 JSON 与 `diag-<SHA-256>` 幂等标识，单包最多 256 KiB。内部复用既有私有文件上传，不增加数据库 schema。
- `GET /v1/diagnostics/:uploadId`：查询所属账号上传回执。
- `GET /v1/diagnostics/:uploadId/content`：读取所属账号已保存内容。

云端未更新时明确提示接口尚未提供；不得将本机导出当成上传成功。超时后重试同一包，不创建不同内容的重复工单。切换账号会清空界面回执；宿主/工作进程在异步操作后复核账号与平台。

## 权限与模型连接异常（2026-11-06 源码修复）

当前任务发现权限版本已改变时，以 `PERMISSION_CHANGED` 停止整轮后续操作，保留已写文件、消息及回执。单次用户拒绝 `DENIED` 与任务权限失效分开；恢复应在当前权限下发送新的明确输入，不能通过换工具绕过失效状态。

模型连接失败和响应流中断分别显示对应原因及已有文件保留提示。诊断保存连接/读流阶段、调用 ID 和经允许列表过滤的连接错误码，不保存错误原文或凭证。无底层错误码时保留未知，不能推测具体网络或供应商原因。本次源码修复尚未更新安装包或生产服务。

## Harness 诊断快捷工具（2026-11-06 源码）

当前对话诊断改用只读检查，不自动恢复图片或重装技能。报告提供「检查当前任务 / 检查模型连接 / 检查工具与服务 / 检查已有成果 / 检查运行环境」五个关注范围，保留完整证据。点击「由内核解释诊断」会将原请求、范围和报告交给同一个 Harness 会话。

Harness 可调用 diagnostic_inspect / diagnostic_repair / diagnostic_verify。修复只能使用检查返回的宿主动作，五分钟内有效、一次性使用；证据变化需重新检查。当前内核修复覆盖已有图片恢复与绑定技能重装，交互授权仍使用原入口。修复后回读验证；原任务的失败记录和原文保持不变。没有模型额度也可执行宿主检查。

兼容接口 chat.diagnose 保留原自动维护行为；新界面使用 diagnostic.inspect。平台工具契约和桌面需要同步发布，本次源码验证不代表安装版或生产服务已更新。设计与验收见 docs/design/Harness统一诊断工具.md。

## 权限切换与详情兜底（2026-11-06 后续源码调整）

按最新产品要求，默认权限为「帮我批准」。权限模式切换不终止整轮对话；正在执行的操作保留，后续操作采用新权限，旧授权清除。等待批准时切换模式，宿主丢弃旧批准结果并重新检查当前权限。账号或对话上下文失效、明确停止操作仍保留原取消边界。本节取代上文“权限版本变化即停止整轮”的源码规则。

失败弹窗补全影响、保留内容及技术详情；历史精简错误记录在读取时根据已保存请求证据补足，缺少证据时明确显示未知，不展示空白详情框。本轮未更新安装版。

## 长上下文传输与草稿续接（2026-11-06 源码）

Harness平台入口与本机代理使用统一HTTP传输预算，默认8MiB，可通过进程环境CPCLAW_HARNESS_MAX_BODY_BYTES设置（256KiB—32MiB）。它按UTF-8 JSON字节计量，不是模型token上下文上限；其他接口限制不随之扩大。平台/health自报harnessMaxBodyBytes。

超限返回HTTP 413及REQUEST_BODY_TOO_LARGE，详情显示接收字节数和上限，不再按socket异常显示“模型连接失败”。检查配置和请求范围后再续接，不盲目重复原请求。旧平台仍可能销毁socket，需先更新平台。

“提交文档段落”仅表示一段保存成功。草稿显示“尚未发布”时，由同一内核读取已有draft、沿用documentKey从下一段提交，complete=true才发布；不会因某段成功自动认定整份文档完成。此次改造未自动修改或补写历史用户草稿。
