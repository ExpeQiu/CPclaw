> 2026-11-05 源码改造：所有新输入统一进入该聊天的持久 Harness 会话。已随 0.0.42 打包、替换本机应用并部署配套云端，见 [发布记录](../docs/verification/unified-harness/发布记录.md)。实现与验收见 [统一运行验收](../docs/verification/unified-harness/验收记录.md)。

## 使用方式

1. 在「设置与诊断」连接企业平台并登录。安装包使用包内 Harness，开发环境可使用受支持的本机检出；内核不可用时明确报错。
2. 新建聊天，直接输入需求。普通问答、澄清、工具执行和文档交付均由同一个内核会话处理；聊天创建时保存会话绑定。
3. 通过「知识来源」、技能、项目材料和应用服务显式关联资源。内核按需调用资源工具读取；CPclaw 不先按问题关键词摘取片段或替内核决定执行步骤。
4. 输入“继续”等文本会作为新的原始输入发送。只有明确未被内核接收的失败输入可通过传输重试入口补投；已接收或受理不明的请求不能重新入队。
5. 停止会取消本轮运行，已收到正文及已提交成果保留。执行状态与任务内容是否完成分别展示。
6. 内核通过文档工具提交一个或多个文件，每份文档可分段暂存；完成标记后才发布文件。保存成功不能证明所有业务目标已完成。

## 上下文与隔离

一个 CPclaw 聊天绑定一个持久 Harness 会话。重启工作进程后恢复原会话，不以筛选后的问答、宿主摘要或另一模型的上下文替代。不同聊天的消息、执行历史、收件箱和内核上下文独立；同项目聊天可共用获准目录及知识库，其他聊天写入资源的变化只有在重新读取时可见。

旧聊天的宿主记录不等于完整内核历史。界面要求显式选择关联只读历史后继续；原文、失败记录和旧草稿保留，供内核通过资源工具读取，不自动重放原输入或复制到其他聊天。

普通运行日志只记录必要关联标识、阶段、用量、错误和回执引用。诊断收集结构化事实；「由内核解释诊断」把证据作为本聊天显式作业交给同一内核，不修改先前答复。文件恢复状态单独展示。

## 已有文件登记与未完成草稿（2026-11-06 源码）

内核使用文件工具、终端或 CLI 生成 Markdown 后，可通过 `register_document(path, filename, expectedHash)` 明确登记为本聊天成果。宿主重新执行文件读取授权、验证 SHA-256，再按原文字节保存成果快照并通知界面。源文件保持原样，后续外部修改不改变已登记版本。未明确登记的普通文件不会自动成为聊天成果；当前成果预览仅支持已有 Markdown 范围，不自动转换 PDF、Word 等格式。

`read_file` 返回的 `sha256` 可作为登记所需版本。读取被拒绝、文件不可读、版本已变化或存储失败时不能声明登记成功。新增工具需要配套平台工具白名单版本；本次源码变更尚未打包、安装或部署。

原生分段文档及旧链路草稿会在聊天卡片和文档列表显示“未完成草稿”，支持只读预览和源文查看，重启后保留。草稿不能直接打开文件、另存为正式成果或作为完成文档编辑；应由内核继续提交。正式提交后，对应原生草稿入口移除并显示成果卡片。旧草稿只读保留，不自动发布或改写历史回答。
