# 请求诊断与日志

0.0.39 起，聊天请求在桌面与云端保存结构化诊断证据。记录用于定位失败阶段与恢复边界，不保证在供应商未返回原因时推断出唯一根因。

## 使用

发生异常后，点击该对话的「自诊断」。系统优先显示具体错误分类、失败阶段、关联请求、模型结束状态及工具参数长度，再显示回复、平台连接与内核检查。若已进入内核但没有工具回执，明确提示操作结果需要核实，不能认定外部操作未发生。

重试使用新 `requestId`，通过 `retryOf` 指向前次请求，沿用 `traceId`；不会覆盖之前的失败快照。正在执行的工具若因进程退出而没有回执，不允许直接重试不确定的外部操作。恢复仍依据原任务身份和已有回执执行，不自动重新提交生成或写入。

旧请求可能只有原始错误文案；没有可用快照时，自诊断说明证据不足，不将其猜测为断网、额度不足或供应商故障。

## 记录内容

- 桌面：聊天、消息、请求、重试关联、应用版本、路由、内核会话编号、阶段、结果、耗时、工具开始与完成状态，以及安全提取的异常类型和代码位置。
- 模型：HTTP 状态、供应商返回的请求编号（如有）、结束状态、`[DONE]` 是否收到、是否正常 EOF、流片段及字节数量、正文长度、工具名称、参数字节数和 JSON 完整性、等待间隔及输出上限。
- 云端：普通聊天与内核模型调用均保存独立记录；内核子请求携带父请求和会话关联。HTTP 失败记录经过归类的接口、状态与耗时，不保存请求正文。

单独缺少 `[DONE]` 不等于失败：若供应商已返回有效结束状态，仍可正常完成。0.0.39 的线上合成请求已观察到 `finishReason=stop`、正常 EOF，但没有 `[DONE]`。

## 常见分类

| 分类 | 已知事实 |
|---|---|
| MODEL_OUTPUT_LIMIT | 模型明确因输出上限结束 |
| MODEL_STREAM_INCOMPLETE | 缺少完整结束状态；不能仅凭该记录区分供应商与网络中断 |
| MODEL_STREAM_TIMEOUT | 等待模型流数据超时 |
| TOOL_FINISH_MISMATCH | 输出了工具调用，但结束状态与工具调用不一致 |
| TOOL_ARGUMENTS_INVALID | 工具参数解析或校验失败 |
| MODEL_EVENT_INVALID | 模型流包含无法解析的事件 |
| MODEL_HTTP_ERROR | 供应商返回非成功 HTTP 状态 |
| LOCAL_SERVICE_FAILED | 本机工具未取得正常回执，操作结果需核实 |
| DESKTOP_PROCESS_INTERRUPTED / PLATFORM_PROCESS_INTERRUPTED | 进程退出时请求仍在途 |

## 存储与访问

桌面证据位于现有 `chat.sqlite` 的 `chat_request_evidence` 表，每次尝试单独保存。云端证据位于持久数据卷的 `request-traces.sqlite`；保留最近 30 天、每账号最多 5000 条，超出时清理较旧记录。它们独立于滚动文本日志。

云端 `GET /v1/me/request-traces/:requestId` 只允许当前账号读取自己的记录；无权限与记录不存在均返回 404。桌面自诊断可在需要时读取当前账号对应的云端证据，云端暂不可用时保留本机记录。

默认不保存完整提示词、模型正文、工具参数、请求头、密钥或供应商错误正文。供应商没有返回请求编号时字段为空，不编造编号。诊断回调或日志落盘失败不会替代原模型结果；会额外记录诊断写入失败事件。
