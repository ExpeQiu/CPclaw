# 项目信息压缩

## 使用方式

在左侧项目名称右侧，点击「信息压缩」图标（位于 ↗ 左边）。面板显示项目路径、可加工文本数量、新增或变化的资料、上次更新时间及未加工材料。

点击「开始整理」或「更新知识」后，将变化的文本交给当前平台模型加工，使用平台模型额度。原文件不移动、不重命名、不删除。整理仅由手动触发，不会后台定时执行。

完成后可在面板查看 Wiki、知识页和本次变更。知识页中的来源按钮在文件夹中显示原始文件。运行时可关闭面板、切换聊天，也可重新打开查看进度；「停止整理」会取消后续处理。

## 产物与信息边界

项目文件夹内生成 `项目Wiki/README.md`，按主题导航并建立原文件到知识页的来源索引。知识页包含主题事实、明确决策、方法、待核实内容，保留数值、条件、原文引用及行号。每次生成的知识页写入独立的 `历史/<版本>/主题/` 目录，首页和发布索引指向当前有效版本，旧页保留供追溯。知识页以资料为单位，跨资料按主题导航；当前版本没有独立的跨资料语义合并与全局矛盾判定步骤。

引用的字符和行号必须与原文相符才能发布；这不能证明 AI 改写在语义上完全正确。AI 加工页会提示复核，观点、推断和资料内的冲突应归入待核实。

## 增量、人工编辑与失败恢复

- 依据原文内容哈希判定变化，按片段缓存完成结果。再次执行相同内容不请求模型，也不重复生成历史版本。
- 知识页被人工修改时保留原页，列入待处理，不覆盖它，也不把修改后的内容自动视为验证过的知识。可以先在原资料补充或修订事实，再人工合并知识页，并恢复此前生成页后重新加工；目前没有自动合并人工知识页的操作。
- 首页被人工编辑时停止更新。请先保存人工改动，将其合并回原资料，再恢复生成首页后更新。生成目录应作为只读输出使用，人工维护的信息建议写在项目其他 Markdown 文件中。
- 失败或停止后，已校验的片段缓存保留，下次手动执行复用。来源在加工期间变化则列入待处理。
- 尚未得到完整响应的模型请求保留原 `requestId`。再次执行复用该编号，不会自动换编号重发。现有平台对已受理请求返回 409，尚无聊天结果回读接口，因此这种不确定结果需要核实原请求，不能保证自动恢复。已完整返回但结构或引用校验失败的响应，在下一次手动更新时可重新加工。
- Wiki 写入与索引发布分别处理；索引发布失败会明确提示，旧索引保留。逐页内容使用不可变版本，检索只读取已发布的清单。

## Agent 检索

当前项目的普通问答优先读取已发布 Wiki 清单，然后检索原文件。每次读取知识页前，检查原文件和知识页的哈希；来源已改动、删除、知识页被人工改动或使用符号链接时，相关页退出检索。历史目录不参与普通文件扫描，Wiki 也不会被再次当成原资料加工。

首版复用本地词语检索，没有新增向量数据库。Wiki 检索有时间、文档数及读取量预算；不代表 Agent 已阅读全部资料。

## 支持与限制

支持 UTF-8 的 Markdown、TXT、CSV、JSON、YAML。单份原文不超过 512KB，最多 500 份文本、合计 8MB；最多 10000 个目录条目、8 层子目录。单行超过 6500 字时提示拆分。PDF、Office、图片和其他格式列出未加工原因，不宣称已经读取。

跳过隐藏文件、依赖与构建目录、凭据命名文件、Wiki 自身以及符号链接。目录规模超限则停止更新，不将未扫描到的来源误判为删除。输入与输出均限制在关联的真实项目目录内。每个项目同时只运行一个整理任务。

## 开发与验收

- `node --test apps/desktop/test/project-wiki.test.mjs apps/desktop/test/project-wiki-service.test.mjs`：真实临时文件、原文引用校验、变化检测、人工编辑保护、历史隔离、越界防护、取消及片段缓存恢复、平台流 RPC 与 Mock 拒绝。
- `node scripts/verify-project-search.mjs` 和 `node scripts/verify-projects.mjs`：已有项目检索和项目文件行为回归。
- `pnpm --filter @cpclaw/desktop exec electron ../../scripts/verify-project-wiki-ui.mjs`：隔离 Electron、真实工作进程和文件、HTTP 模型夹具；覆盖入口位置、扫描、生成、查看来源、增量更新、无变化不调用模型和宽窄布局。
- 桌面截图保存在 `docs/verification/project-wiki/`。上述验证不等同于真实模型内容质量验收、已安装应用验证或已发布安装包。
