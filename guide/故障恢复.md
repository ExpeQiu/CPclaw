# 故障恢复

按契约收敛，不把未知结果报成功。

| 场景 | 预期 |
|---|---|
| 进程崩溃 / 重启 | 活动 Run 标为中断；不自动继续执行 |
| 写前中断 | 不产生半份备份或半份报告成功回执 |
| 写后中断 | 已落盘文件保持待核实，不记为业务成功 |
| 断网 | 日志/上传入 Outbox，连通后按批次补传；同批去重 |
| 撤销竞态 | 权威台账回放后，旧备份不能重新开放已撤权资源 |
| 上传/回复回执丢失 | 查原事务与持久化回执；不换设备重跑同一 commandId |
| 技能市场/聊天报「登录凭证无效」 | 刷新令牌是单次使用语义；本机令牌与平台不一致时，重新登录一次即可恢复 |

## 排障顺序

本机「设置与诊断」已保存配置 → 环境变量 → 网络（可用设置页「测试连接」）→ 余额/额度 → 日志（`~/Library/Application Support/CPclaw/logs`）→ Mock 复现。

内核状态看标题栏徽章与设置页「推理内核」；`desktop-settings.json` 已写出的字段不会被 `.env` 自动盖回，除非点「从 .env 同步」。

## 诊断包

只读；默认脱敏。支持渠道提交前预览范围。禁止借诊断抓取完整会话、记忆或目录正文。

## 对话自诊断

对话顶部的「自诊断」检查：账号与平台会话、推理内核（deepseek-harness）、最后一轮任务全链路、Skill 本机制品、以及相关结构化日志摘录。正在执行的任务须先停止或等待结束；诊断期间阻止发送、切换服务和账号变更，避免修复与执行互相覆盖。

- 检查结果区分异常、通过与提示。「检索未找到相关片段」属于提示，不当作故障。
- 报告含时间线（平台→模型→工具→Skill→落盘）与近期日志（脱敏，不含会话正文）。
- 旧版留下的空白服务回复，可从本地真实回执恢复执行摘要（聊天区只写条数与右侧核对提示，不展开逐步清单）；修复后回读数据库验证。任务结束后遗留的执行中步骤会校正为中断。原始失败状态及回执保留在右侧操作面板，恢复摘要不代表原任务完成。
- 绑定 Skill 制品缺失时可驱动白名单重装并校验；账号不一致可确认后解除绑定。不自动改写 `SKILL.md`，不静默重跑外部扣费任务。
- 报告右上角「执行修复」按检查结果驱动：即梦重新授权、重启工作区进程、打开设置/操作面板、Skill 白名单修复、按平台能力重裁服务目录、重试本轮回复等；需确认的项会先弹出说明。修复后自动再跑一轮自诊断。
- 平台连接可用时刷新登录会话；网络或登录检查失败时说明下一步，不推测服务端根因。
- 桥接缺失（`cpclaw.workspace` 不可用）时提示重启应用，并写入 UI 日志。
- 同一轮重复诊断不重复计数；同一对话记录多轮同类异常，提示进一步排查。
- 新回复遇到异常时自动保留应用执行摘要。已有生成或写入回执时禁止整轮重试；宿主确认全部为只读准备时可继续原请求，原回执追加保留。恢复前先核实原任务，避免重复生成。
- Harness 关闭后最多等待 2 秒确认子进程退出；超过上限仍报错。无法检查进程状态时也不会报成功。

文档工作区仍从左侧「对话文档」入口打开。设计见 `docs/design/自诊断升级.md`。

### 模型额度不足与异常提醒

模型tokens额度与即梦积分分别核算。开始任务前会核实模型可用额度及下一次请求所需最低预留；不足时暂停，不再继续模型或工具准备。网关429会保留明确的额度/并发原因，自诊断会读取当前额度进一步区分。

额度不足时自动弹窗，显示原因、影响、已保留进度和申请入口。当前额度申请采用自动审批：填写新增量后提交，服务端为当前账号增加额度并回读确认；每次可申请1至100万tokens，默认100万。原已用额度、未知用量、并发限制及即梦积分保持原账目。响应丢失时点击「核实原申请结果」，沿用已保存的申请编号，不重复增加。

申请批准但可用额度仍低于最低预留时，会继续提示不足；达到条件后显示「新额度已到账」。没有外部副作用时可继续原请求，已有外部执行时先检查并恢复原任务。旧平台未声明额度申请能力时，提示先更新平台服务，不显示虚假的审批成功。

其他异常同样说明原因、影响、保留进度和下一步。授权/登录等阻塞问题弹窗；网络/并发等暂时问题主要在聊天内提示；图片交付恢复后更新原提醒，原始错误保留在技术详情。设计与文案见 `docs/design/异常提醒与额度申请.md`。

### 生图成功但没有图片 / 中断后续接

自诊断根据本轮持久化的画布、提交 ID、资源 ID 和文件回执分别核实生成与交付，不把历史参数失败等同于当前图片失败。

自诊断使用应用内系统维护权限，已实现的恢复动作优先于普通对话权限执行。点击「自诊断」后会自动尝试查询原提交及补下载；无需逐条授权或再点一次续接。仍在处理中的原任务可稍后再次查询；需要官方登录交互或权限不具备时明确报告阻塞。

- 已生成且本机已有图片：自动校验文件类型、大小和哈希，恢复预览并把成果入口补充到原消息。平台断网也可恢复本地文件；原始执行错误和回执保留。
- 已提交但终态未知，或成功图片尚未下载：自动按原提交查询状态、核实资源并补下载，不创建节点、不重新生成。原任务仍在处理时明确显示待查询，稍后可点「续接已有任务并恢复图片」再次查询；会话原本的权限模式保持不变。
- 大图保留原文件，预览最长边不超过2048像素；可点「打开原图」。本机读取上限64 MiB；超限、解码或校验失败会保留具体原因。预览失败不会再抹掉已成功下载的路径与校验回执。
- 图片恢复回执落入原任务，切换聊天或重启工作区后可回读；只允许读取当前账号和对话的成果目录，拒绝指向目录外的软链接。
- 检查完成、修复验证、图片交付分别显示。无修复时记录 `repairState=none, verified=0`；有剩余故障时明确显示待处理数量。图片交付状态表示文件校验及预览准备成功，不表示用户已确认画面质量，也不代替其他业务目标的验收。

节点 ID 由宿主按当前 CLI 的10位 Crockford Base32规范生成。诊断细分节点 ID、CLI 参数、终端参数、模型步骤上限、网关502及图片交付问题，历史授权失败在后续服务端检查通过后不再作为当前授权故障。

诊断报告含「经验与防复发」：已观察问题和已验证修复分开展示，同类任务涉及次数按任务去重。诊断及修复台账保存在本机聊天数据库的 `diagnostic_runs` / `diagnostic_lessons`，按平台和账号隔离。该经验只记录结构化问题与固定维护策略，不包含会话正文或密钥；再次遇到同类问题时加载已有记录，验证过的策略优先展示。

验证：`node --test apps/desktop/test/*.test.mjs`；真实界面与独立工作进程恢复验证：`apps/desktop/node_modules/.bin/electron scripts/verify-media-recovery.mjs`。测试使用隔离数据库，不重新提交生成任务。

### 技能市场报「登录凭证无效」

平台续期是**单次使用**语义：每次续期都轮换刷新令牌，旧令牌立即作废。桌面端所有远程调用（技能市场、聊天、知识库、报告工作区）都要先换取访问令牌。

若旧版本在同一时刻发起多次续期，先到的请求会作废后到请求持有的令牌，后到的请求得到 401，而**最新令牌从未写回本机**——本机令牌从此与平台永久不一致，表现为技能市场首屏直接报「登录凭证无效」。

排查顺序：

1. 对比两端令牌哈希是否一致。本机 `~/Library/Application Support/CPclaw/accounts/<员工>/session.json` 存的是令牌原文，平台 `sessions.refresh_hash` 存的是其 SHA-256 前缀；不一致即确认此问题。
2. 平台侧 `audit_log` 中同一 `session_id` 会出现密集的 `refresh` 记录（1 秒内多次），可佐证并发续期。
3. 恢复方式：在「设置」里重新登录一次，或执行 `CPCLAW_PASSWORD=... node scripts/repair-desktop-session.mjs` 重建本机会话。

已修版本对续期做了**单飞收敛**：同一时刻只发一次续期请求，其余调用方复用同一结果；并用文件锁覆盖多个桌面实例的跨进程竞争。回归见 `apps/desktop/test/session-refresh-race.test.mjs`，线上核验见 `scripts/verify-market-session.mjs`。

验证：`node --test apps/desktop/test/chat-diagnostics.test.mjs`、`pnpm --filter @cpclaw/harness-adapter test`、`pnpm test:desktop:chat`。诊断和复发记录保存在本机聊天数据库，不上传完整对话。日志目录：`CPCLAW_DATA_DIR/logs/`。

### 报「应用服务目录无效」

平台对 `/v1/chat/stream` 的 `serviceTools` 做**类型白名单**校验。桌面端固定提供 `browser-page`（`WEB`）与本机拓展（`APP`），平台版本较旧时只接受 `CLI/MCP`，目录里一旦混入平台不接受的类型，**整轮对话都会被 400 拒绝**，表现为助手无回复或「应用服务目录无效」。

判定（两条同时成立即确认）：

1. 聊天记录里助手消息 `state=error`、`error` 含「应用服务目录无效」或「不接受本机服务目录」。
2. 平台 `GET /health` 返回的 `serviceTypes` 不含 `WEB`/`APP`（旧平台没有该字段，也按最保守口径处理）。

排查顺序：

1. 看平台能力：`curl http://<平台地址>/health`，确认 `serviceTypes` 取值。
2. 看平台部署版本是否落后于桌面端；平台白名单以 `packages/contracts/src/service-catalog.ts` 为单一真源。
3. 更新平台：确认 3928 仅对本机出口 IP 放行后执行 `CPCLAW_FIREWALL_ACK=yes CPCLAW_FIREWALL_SOURCE_IP=<本机出口IP> bash scripts/deploy-platform-remote.sh`（脚本会先备份数据库与镜像，再重建容器并收紧 iptables）。

桌面端已内置兼容：发送前按平台自报能力裁剪目录，剔除平台不接受的类型并修正当前服务，旧平台也能正常对话；被裁掉的服务在本轮不可用，平台更新后自动恢复。若平台未声明能力，按最保守口径（`CLI/MCP`）下发。自诊断识别该错误为「平台拒绝服务目录」，可点「执行修复 → 按平台能力重裁服务目录」清除能力缓存并重试。

### 即梦已登录但授权不足

以服务端 `oauth_scope_insufficient` 回执为准，不能只看本地 `auth status`。自诊断会识别旧版本 discover 内嵌的失败回执；能力发现也会将账号或画布检查失败报告为不可用。CLI 已是官方当前版时不重复安装。

调用普通 `auth login` 时，只有宿主已收到明确的授权不足回执，才会单独请求「重新授权即梦账号」批准，并由宿主添加 `--force`。模型仍不能自行传入 `--force`、更换 profile 或取得设备授权引用；已有授权挑战时继续等待，不重复发起。用户完成官方授权后须验证服务端账号和原画布/提交，恢复原任务身份，不自动生成或重复扣费。
