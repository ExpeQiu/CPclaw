# 本地验证

`bash scripts/verify.sh` 检查 Mock 健康进程、包测试、未签名报告、桌面重复点击、Harness 文本流和取消，并接着检查本机平台的登录、撤销和额度。失败时返回非零。

只跑平台：`bash scripts/start-platform.sh`、`bash scripts/stop-platform.sh`、`bash scripts/verify-p1.sh`。P2–P5：`bash scripts/verify-p2.sh`、`bash scripts/verify-p3.sh`、`bash scripts/verify-p4.sh`、`bash scripts/verify-p5.sh`。验证时设置 `CPCLAW_PLATFORM_SEED=fixture` 和至少 32 位的 `CPCLAW_SESSION_SECRET`。fixture 口令只用于 Mock，不能当作生产账号。

```bash
cp .env.example .env
bash scripts/start.sh
bash scripts/verify.sh
bash scripts/stop.sh
```

`AI_MOCK_MODE` 只有精确值 `true` 能通过。`start.sh --target docker|cloud` 仍会失败退出（P0 本机健康进程合同）。结果写到本机 `~/Library/Application Support/CPclaw/evidence/p0-02a-last.json`。

**防火墙（强制）**：公网 + fixture 口令不可裸奔。部署前须把 `${REMOTE}:3928` 限制为**本机出口 IP**，并设置 `CPCLAW_FIREWALL_ACK=yes`。脚本在未确认时拒绝部署。可再设 `CPCLAW_FIREWALL_SOURCE_IP=<本机出口IPv4>`，由部署脚本写远端 iptables 白名单；**云安全组仍须另行收紧**。

## 真实 MiniMax 报告链路

先在本机私有 `.env` 配置 `MINIMAX_API_KEY`（文本订阅 Key 可用于文本接口）。执行：

```bash
pnpm build
node scripts/verify-minimax.mjs
```

脚本启动隔离的本机控制面，以 fixture 身份登录，经桌面同一个 workspace-client/worker 调用真实 MiniMax-M3，验证待审时不落盘、接受后报告落盘、随机材料事实与逐段来源、调用次数累计。会运行文本、流式、工具 echo 与客户端取消/超时检查，产生实际模型用量。证据和报告在脚本输出的 `/tmp/cpclaw-minimax-*/` 下。退出关闭测试进程，不改现有平台数据。

持续使用时，平台和桌面均设 `CPCLAW_REPORT_MODEL_MODE=real`，保持当前 fixture 基础的 `AI_MOCK_MODE=true`。平台通过私有 `.env` 读取密钥；桌面用 `CPCLAW_PLATFORM_URL` 指向该平台，并使用该平台登录产生的会话。桌面选择明确的普通文本文件（8 KB 内、最多 64 段）作为材料，点击暂存报告，接受后才写 `report.md`。目录授权在调用前和落盘时检查。取消或模型失败不创建待审结果，未知用量不记为零。

本接口是单次受控报告生成，不运行模型工具循环；不代表 Harness 已与真实模型完成工具编排，也不代表远程平台已经部署该增量。现有远程 Mock 地址不可直接当作真实报告网关。

2026-10-23 实测：本机真实报告链路已通过。一次报告调用记录输入 337、输出 307 token，约 4.8 秒；只作观测，不代表质量/费用/时延达标。流式用 `finish_reason=stop` 判断完整结束，支持 MiniMax 在用量块后直接 EOF；缺少正常结束原因则拒绝。
