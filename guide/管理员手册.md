# 管理员手册

覆盖本机平台部署、备份、升级与撤销。真实云部署与签名分发仍受阻（见 `docs/decisions/005`）。

## 部署

1. 确认运行时：Node 22、darwin/arm64（当前验证矩阵）。
2. `bash scripts/start-platform.sh` 启动平台；`bash scripts/stop-platform.sh` 停止。
3. 健康检查失败必须非零退出；不要用 Agent 会话内 `nohup` 维持长期服务。

## 备份

- 管理端或 `POST /v1/admin/backup` 写出 `platform-*.sqlite`。
- 工作区可用宿主 `backupWorkspace`；备份目录在数据目录下 `backups/`。
- **权威台账** `authority-ledger.json` 独立于 sqlite。撤权写入台账，恢复旧备份后会回放，避免重新开放已撤权原文。

## 恢复

1. 停止平台进程。
2. `restorePlatformSqlite(dataDir, fileName)` 或按运维脚本拷贝备份并旁路保留当前库。
3. 重新 `openPlatform`：会迁移兼容 schema，并 `applyAuthorityLedger`。
4. 验证：已撤权文档不可检索/引用；会话撤销仍有效。

## 升级

1. 结束活动任务。
2. 写出/核对未签名制品清单（`release/manifest-*.json`）。`signed=false` 时不得宣称可上生产。
3. `verifyUpgradeGate`：目标 schema 高于本机支持则**拒绝打开**，旧库旁路保留，不自行降级解释。
4. 签名/公证账号未提供前，安装包验证保持受阻。

## 撤销

- 设备会话、员工停用、原文、渠道配对与会话绑定均可撤销。
- 关键撤权进权威台账；恢复演练必须覆盖「备份 → 撤权 → 恢复旧备份 → 仍不可见」。
