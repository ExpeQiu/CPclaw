# 桌面知识库

右侧「知识库」面板上方为「关联 企业知识库（wiki）」，下方为「关联 个人知识库（wiki）」。两类均支持多个本地目录及 CPclaw 平台知识库。桌面需登录，平台需升级到包含 `/v1/knowledge` 的版本；本次源码更新不自动发布远程服务。

## 关联与管理

1. 点击对应区域的「＋ 关联知识库」。
2. 选择「本地目录」后，通过文件夹选择器选择目录。首次关联建立索引；文件修改后点击「更新」。
3. 选择「CPclaw 平台」后，选择当前账号可访问的知识库并关联。个人可新建自己的库；管理员可新建企业库，并填写有权访问的员工编号。
4. 平台库关联后，点击「查看」管理文档。个人库由本人维护，企业库由管理员维护；可新建或编辑 Markdown/TXT 正文。并发修改时旧版本保存会被拒绝，需重新打开文档。
5. 「修改名称 / 权限」用于改名和更新企业库成员。「解除关联」仅移除当前账号的桌面连接与来源选择，不删除平台库、本地文件或其他账号的连接。

企业库默认仅管理员与指定成员可访问；个人库即使管理员也不能读取。本地目录归为企业来源只影响分类，不会上传或共享给其他员工。

## 在问答及报告中使用

点击输入框旁「知识来源」，勾选当前对话使用的库并保存；新对话会先创建本地会话。最多选择 12 个，选择随对话保存。通过对话要求生成报告时，知识片段与用户要求一起提供给模型，生成的文档沿用原有文档工作区保存流程。

回答下方展示「知识库参考资料」，包含企业／个人类型、库名、文档及行号；点击可查看当前原文。本地文档也可在文件夹中显示。回答正文及报告中的引用由模型生成，来源列表展示实际送入模型的片段，不表示模型一定采用了每一份资料。历史引用保留当时的片段；查看平台原文仍重新检查权限，文档可能已更新。

原有「审阅成果」中的单份报告材料路径移到该面板内，仍沿用原来的单文件报告流程，不使用对话的知识来源选择。

## 更新和边界

- 本地仅索引 `.md` / `.txt`，忽略隐藏项、符号链接和构建依赖目录；最多 500 份文档、8MB、8 层目录，单文件最多 512KB。超限会提示缩小范围，不静默截断索引。
- 更新失败保留上次索引，不作为新的成功更新；需更新成功后继续检索。目录丢失或变化时阻止读取。
- 平台单库最多 500 份文档、总正文 200 万字，单篇最多 48000 字。每次使用都重新读取并检查权限，不把远程正文长期缓存成可离线绕过权限的资料。
- 平台断网、来源撤权或选中目录不可用时，本次回复失败并提示原因，修复来源或取消勾选后重试。
- 关联按平台地址及账号隔离，切换账号清空当前展示并加载对应连接。
- 首版使用本地关键词片段检索，每次最多 6 份片段、4000 字；不包含向量搜索、自动同步、PDF 或其他平台连接器。
- 平台知识库容器与原有需审核的 Wiki 发布链路分别保存；本次不自动迁移原有发布页或旧个人笔记导入记录。

## 接口

`POST /v1/knowledge` 使用当前平台访问令牌，主体为 `{ action, input }`。

| action | input | 行为 |
|---|---|---|
| list | `{}` | 列出有权访问的库与当前角色 |
| save | `{ id?, scope, name, members? }` | 创建或修改库；scope 为 enterprise / personal |
| read | `{ id }` | 再次检查权限后返回库及正文 |
| document-save | `{ id, documentId?, revision?, title, body }` | 新建或按 revision 修改文档 |

新表 `kb_libraries`、`kb_documents` 在平台启动时创建，不改原有 Wiki 表；写操作进入平台审计日志。桌面连接、索引与来源选择保存在桌面 SQLite 的独立表中。
