# 桌面知识库

右侧「知识库」面板上方为「关联 企业知识库（wiki）」，下方为「关联 个人知识库（wiki）」。两类均支持多个本地目录及 CPclaw 平台知识库。桌面需登录，平台需升级到包含 `/v1/knowledge` 的版本；本次源码更新不自动发布远程服务。

## 关联与管理

1. 点击对应区域的「＋ 关联知识库」。
2. 选择「本地目录」后，通过文件夹选择器选择目录。首次关联建立索引；文件修改后点击「更新」。
3. 选择「CPclaw 平台」后，选择当前账号可访问的知识库并关联。个人可新建自己的库；管理员可新建企业库，并填写有权访问的员工编号。
4. 平台库关联后，点击「查看」管理文档。个人库由本人维护，企业库由管理员维护；可新建或编辑 Markdown/TXT 正文。并发修改时旧版本保存会被拒绝，需重新打开文档。
5. 「修改名称 / 权限」用于改名和更新企业库成员。「解除关联」仅移除当前账号的桌面连接与来源选择，不删除平台库、本地文件或其他账号的连接。

企业库默认仅管理员与指定成员可访问。企业文档保存后进入待审，审核通过前成员不能引用；再次修改会使已发布版本重新待审。原文撤权后，派生页不能继续读取。个人库即使管理员也不能读取，仍由本人直接维护。本地目录归为企业来源只影响分类，不会上传或共享给其他员工。

## 在问答及报告中使用

点击输入框旁「知识来源」，勾选当前聊天使用的库并保存。最多选择 12 个，选择随聊天保存。统一 Harness 路径向内核提供已关联库的目录标识；由内核明确读取目录及具体文档，按字符偏移分页获取完整内容，不预先按用户话题选片段。

正文引用由内核形成。工具回执记录实际读取的资源；CPclaw 不生成表示“模型已采用”的引用结论。平台库每次读取重新核实权限；撤权后返回结构化不可用回执，不能靠历史目录取得新内容。已进入内核历史的内容不会因撤权自动抹除。

原有「早期记录」仅用于查看既有数据，不启动新的独立报告模型。

## 更新和边界

- 本地仅索引 `.md` / `.txt`，忽略隐藏项、符号链接和构建依赖目录；每个知识库最多 500 份文档、8MB、8 层目录，单文件最多 512KB。容量超限时，请按主题拆分为多个文件夹，再逐个关联，每个文件夹均需符合限制；对话中通过「知识来源」选择使用，单次最多选择 12 个知识库。不静默截断索引。
- 更新失败保留上次索引，不作为新的成功更新；需更新成功后继续检索。目录丢失或变化时阻止读取。
- 平台单库最多 500 份文档、总正文 200 万字，单篇最多 48000 字。每次使用都重新读取并检查权限，不把远程正文长期缓存成可离线绕过权限的资料。
- 平台断网、来源撤权或目录不可用时，资源调用返回失败事实，由当前内核处理后续步骤；宿主不合成替代答案。
- 关联按平台地址及账号隔离，切换账号清空当前展示并加载对应连接。
- 当前内核资源工具支持目录与逐文档分页读取；不包含向量搜索、自动同步或 PDF 正文解析。旧关键词预检索不再用于新聊天路径。
- 平台知识库容器与原有需审核的 Wiki 发布链路分别保存；本次不自动迁移原有发布页或旧个人笔记导入记录。

## 接口

`POST /v1/knowledge` 使用当前平台访问令牌，主体为 `{ action, input }`。

| action | input | 行为 |
|---|---|---|
| list | `{}` | 列出有权访问的库与当前角色 |
| save | `{ id?, scope, name, members?, baseUpdated? }` | 创建或修改库；scope 为 enterprise / personal |
| read | `{ id }` | 再次检查权限后返回库及正文 |
| document-save | `{ id, documentId?, revision?, title, body }` | 新建或按 revision 修改文档 |

新表 `kb_libraries`、`kb_documents` 在平台启动时创建，不改原有 Wiki 表；写操作进入平台审计日志。桌面连接、索引与来源选择保存在桌面 SQLite 的独立表中。

企业管理员也可在云端 `/admin` 的「企业知识库」页维护同一批企业库、成员和文档。管理台不开放员工个人库；文档修改继续检查 revision，名称及权限修改可用 baseUpdated 拒绝过时提交。
